## 61 — 떠 있는 셸 지킴이를 보고 끝내기
- 찾기: `ps -A -ww -o pid=,ppid=,uid=,lstart=,command=`(LC_ALL=C) 의 줄에서 `…/host.js <소켓> <데이터 폴더>` 꼴만. 소켓이 `<데이터 폴더>/ptyhost-v<n>.sock` 이거나 `<임시>/taskminal-<해시>-v<n>.sock`(해시가 데이터 폴더와 맞음)일 때만 지킴이로 본다 — 데이터 폴더에 공백이 있어도 읽는다. 다른 사용자 · 다른 프로그램 · 모양이 다른 줄은 버린다(`src/shared/host-scan.ts`).
- 들여다보기: 지킴이마다 `hello` → `list` → `stats` 를 한 번 물어 셸 수 · 실행 중인 명령 · 붙은 연결을 채운다(2초). 답이 없으면 '응답 없음'. **스파이크 결과**: 두 번째 연결이 묻고 끊어도 붙어 있는 손님의 셸 · 출력 · 떨어진 시간 · 못 본 알림이 그대로이고, 판 번호가 다른 `hello` 에도 답한다(`ptyhost-core.test.ts` 시험 둘).
- 지킴이 `stats` 답에 선택 칸 `clients`(연결 수) — 프로토콜 번호는 올리지 않았다(0.2.0 지킴이를 '옛 판' 으로 만들지 않게). 이 칸이 없는 옛 지킴이는 셸의 `attached` 로 대신한다.
- 끝내기(`host:others-end`): ① 다시 훑어 같은 pid · 시작 시각 · 소켓이 그대로 ② 다시 물어 붙은 앱이 없음 → 그때만 `shutdown`. 사라짐 · pid 재사용 · 그 사이 앱이 붙음 · 응답 없음이면 **아무것도 보내지 않는다**. 신호(SIGTERM)는 쓰지 않는다 — 답 없는 지킴이는 여기서 끝내지 않는다. 지금 앱의 지킴이는 목록에도 없고 대상도 될 수 없다.
- 화면: 붙은 앱이 있거나 응답이 없으면 끝내기 단추가 없다. 확인 글에 셸 수 · 실행 중인 명령 수. 끝내라고 보낸 뒤 바로 한 번 · 3초 뒤 한 번 다시 읽어 '끝냈어요 / 아직 떠 있어요'. 목록은 칸을 열 때 · '다시 읽기' · 끝내기 뒤에만 읽고(주기 없음), 읽기마다 번호를 붙여 늦은 답을 버린다. main 은 훑기와 끝내기를 차례로 돌린다.
- 범위 밖: 자동 정리 · 원격 서버의 지킴이 · Windows(named pipe — 빈 목록) · 개발/시험 실행이 지킴이를 남기는 원인.

## 62 — worktree 만들 때 환경 준비 · 공유 폴더
- `links`(10개까지 · 중복 금지): 원본에서 gitignore 되고 추적하지 않는 폴더 · 일반 파일만. 원본 경로의 어느 마디든 심볼릭 링크면 거절(`..` · 절대 경로 · `.git` 도). 대상에 **아무것도 없을 때만** 원본 절대 경로를 가리키는 링크를 만든다 — 이미 있으면 그대로(`이미 연결됨` / `기존 것 보존`). 순서는 복사 → 링크 → 명령. 서명에 links 가 들어가 미리 본 뒤 바뀌면 '다시 미리 보세요'.
- 미리보기에 링크마다 '원본과 함께 바뀌어요', 신뢰 안내도 그에 맞게 바뀐다. **경고 둘(검토에서 더함)**: 대상 worktree 에서 Git 이 그 경로를 무시하지 않으면(`.gitignore` 의 `이름/` 은 폴더만 — 링크는 폴더가 아니다) '⚠ Git 이 무시하지 않아요' · 복사할 경로와 겹치는 링크는 미리보기에서 거절.
- 이어 가기: 워크트리 관리 패널에서 만든 것이 확인됐고(`created`) 일감 폴더에 환경 설정이 있으면 만들기 답에 `environment: true` 가 실리고, 패널이 56단계의 '카드 → 환경 준비' 길로 넘어가 미리보기까지 읽는다. **자동 실행은 없다.**
- 넣지 않은 곳: 새 일감의 '새 git worktree 에서 시작' · 이슈에서 만들기 — 만든 뒤 일감이 새 worktree 에서 열려 원래 저장소가 '원본' 이 아니게 된다(main 은 열린 일감 폴더만 원본으로 허용한다. 새 권한 규칙이 필요). 병렬 worker — 미리보기를 확인할 사람이 없다.
- 중간 실패: 만든 파일 · 링크는 남기고 기록에 무엇을 만들었는지 적는다. 다시 시도는 새 번호로 미리보기부터(있는 것은 건너뛴다). Windows 는 폴더를 junction 으로, 못 만들면 준비 전체 실패.

## 63 — 에이전트 안내를 Codex · 터미널까지
- 먼저 58b 확인: 앱이 띄우는 것과 같은 인자(`-p` · stream-json 입출력)에 `--append-system-prompt <안내>` 를 붙여 실제 claude 를 **한 번** 불렀다 — "사람 확인이 필요할 때 · 다른 대화에 맡길 때 쓸 명령" 에 `taskminal notify …` · `taskminal chat new …` 를 답했다(앱은 띄우지 않음).
- 대화 pane 의 Codex: `thread/start` · `thread/resume` · `thread/fork` 의 `developerInstructions`(codex-cli 0.169.0 의 생성 스키마로 확인).
- 터미널: 새 셸에 `TASKMINAL_AGENT_GUIDE`(안내 글) · `TASKMINAL_CODEX_GUIDE`(`developer_instructions=<TOML 글>`) → zsh 셸 통합의 `claude` · `codex` 함수가 그 실행의 인자로만 붙인다. 상태 훅 변수와 따로라서 하나만 있어도 감싸고, 세션 끝 기록은 상태 훅이 있을 때만 남긴다.
  - codex: `codex -c '<값>' debug prompt-input` 의 developer 메시지에 안내가 글자 그대로 들어가는 것을 확인했다(API 호출 없음).
  - claude: `--append-system-prompt` 는 대화형 · 비대화형 모두에서 된다(공식 CLI 문서 "All five work in both interactive and non-interactive modes").
- 덮지 않기: 사용자 codex `config.toml` 맨 위에 `developer_instructions` 가 있으면 Codex 에는 주지 않는다(`-c` · `developerInstructions` 가 그 키를 덮는다 — 대화 pane 은 그 실행의 `CODEX_HOME` 것을 본다). 사용자가 `--system-prompt*` · `--append-system-prompt*` 를 준 claude 실행은 그대로 넘긴다.
- 추가 계정 TUI: claude 는 안내도 붙인다(덧붙이기라 덮지 않는다). codex 는 주지 않는다(그 계정 설정을 여기서 보지 않는다).
- 설정은 58b 의 '에이전트에게 Taskminal 명령 알려 주기' 하나를 같이 쓴다(다음에 띄우는 대화 · 새 셸부터).

## 64 — Jira 쓰기: 상태 전환 · 댓글
- 쓰는 요청은 둘뿐이다. `POST /rest/api/3/issue/{키}/transitions` 는 성공이 204, `POST …/comment` 는 ADF 본문(줄마다 문단)이고 성공이 201. 전환 목록은 `GET …/transitions` 로 메뉴를 열 때마다 읽는다(주기 없음). 토큰은 main 밖으로 나가지 않는다.
- **한 번만**: Jira REST 에는 멱등 키가 없어 main 의 쓰기 기록(이번 실행 · 200개)이 요청 번호마다 한 번만 보낸다.
  - 같은 번호가 진행 중이면 그 요청에 합친다. 끝난 번호는 저장한 결과를 돌려준다. 같은 번호에 다른 내용이 오면 거절한다.
  - 4xx 는 '안 됨' 으로 확정한다. 응답 끊김 · 시간 한도 · 5xx 는 '됐는지 모름' 이고 자동으로 다시 보내지 않는다.
- **다시 확인**(같은 번호): 먼저 이미 됐는지 보고 안 됐을 때만 다시 보낸다.
  - 전환은 이슈 상태가 목표인지 본다. **보내기 직전에 상태를 한 번 읽어 두고**, 그때 이미 목표였으면(같은 상태로 도는 전환) 상태로는 알 수 없으니 '됨' 으로 단정하지 않고 모름으로 둔다(리뷰에서 더함). 그 직전 읽기가 실패하면 보내지 않는다(안 됨).
  - 댓글은 최근 20개에서 내 계정이 요청 시작 뒤(시계 차이 1분 허용) 쓴 같은 글을 찾는다.
  - 인증이 바뀐 뒤에는 옛 번호를 이어 확인하지 않는다.
- 전환은 방금 읽은 목록에 있던 것만 보낸다(인증이 바뀌면 그 기억을 비운다). 성공하면 연결한 이슈를 다시 읽어 일감 머리에 남긴다. 그 사이 일감의 연결이 다른 이슈로 바뀌었으면 읽지도 고치지도 않는다.
- 화면(`shared/jira-head.ts` 모델 + `JiraTaskHead`):
  - 확인 창을 연 순간 키 · 전환 · 글 · 번호를 떠 둔다.
  - 보내는 중에는 단추를 막는다. 읽기 · 쓰기마다 번호를 붙여 늦은 답을 버린다.
  - 입력 중인 댓글은 보내기에 성공할 때까지 남는다.
  - 다른 일감에 갔다 오면 보내는 중이던 것을 main 기록에 묻는다.
  - 토큰이 있을 때만 단추가 보인다(이슈 패널의 읽기 · 저장 · 지움을 따라간다).
  - 메뉴 · 확인 창은 body 에 그린다. 다른 일감으로 가면 닫는다.
- **됐는지 모르는 쓰기가 남으면 그 이슈의 새 쓰기를 막는다**(리뷰에서 더함). 새 번호로 다시 보내면 Jira 에 두 번 갈 수 있기 때문이다. 결과 줄의 '다시 확인' 으로 정하거나, '결과 지우기' 로 사용자가 넘긴 뒤에만 새로 보낸다.
- 범위 밖: 담당자 · 필드 바꾸기, 전환 화면(필수 필드가 있는 전환은 Jira 가 400 으로 거절 → '다시 골라 주세요').

## 65 — 파일 빨리 열기 · 내용 찾기
- main `WorkspaceSearch`: 파일 목록은 `git ls-files -co --exclude-standard -z`(2만 개까지 · git 저장소가 아니면 빈 목록), 내용 찾기는 `git grep -n -I -F -i -z --untracked -e <글> -- .`(500줄 · 줄당 300자 · 10초 · 폴더마다 한 번에 하나). 인자는 배열 · 셸 없음 · `-e` 뒤에 줘서 `-` 로 시작하는 글도 옵션이 아니다. 민감 파일(`.env` · 키 — 파일 보기와 같은 규칙)은 목록 · 결과에서 빼고 결과 글의 비밀값은 가린다.
- ⌘P: 범위 '파일' 을 **맨 끝**에(앞 범위까지의 ⇥ 횟수가 그대로). 이름에 맞은 것을 경로에만 맞은 것보다 위에, 전체 범위에서는 글자 그대로 든 것 8개까지만(퍼지는 수만 개 경로의 거의 전부에 맞는다) 다른 묶음 뒤에. 파일 범위는 퍼지 · 50개 · 빈 찾기에도 목록. 목록은 ⌘P 를 연 동안 **파일이 필요해질 때(글을 치거나 파일 범위) 한 번** 읽는다(로컬 일감만 — 리뷰에서 바꿈: 일감 이동만 하려고 열 때 git 을 부르지 않게). 충돌 중인 파일이 단계마다 나오는 것은 한 줄로 합친다.
- 파일 보기: '내용 찾기' 칸 — 두 글자부터, 입력이 멈춘 뒤(200ms) 한 번, 번호로 마지막 요청의 답만 받는다. 결과 줄(`경로:줄` + 그 줄)을 누르면 그 파일의 폴더로 옮겨 그 줄 세 줄 위부터 소스로 보인다. 안내: 찾는 중 · 없음 · 500줄 상한 · 시간 한도 · 실패.
- 범위 밖: 원격 일감 · 정규식 · 바꾸기.
