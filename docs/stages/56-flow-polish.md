## 비동기 칸 (계획의 세 칸)
- 7 워크트리 목록: 패널을 열 때 한 번 + '준비 기록 다시 확인' 때 한 번(1초 주기 기록 읽기와 따로), root 가 바뀐 뒤 온 답은 `alive()` 로 버림. 첫 워크트리 자동 고르기는 열 때만 — 다시 읽기가 직접 입력에서 비운 경로를 채우지 않는다. 워크트리 패널이 읽는 중 · 만드는 중이면 '환경 준비…' 꺼짐(e2e 로 붙잡아 확인).
- 8 저장소 답: 칸이 비고 GitHub 일 때만 묻고, 묻는 중이면 겹치지 않는다(칸이 차면 다시 묻지 않음). 답이 왔을 때 아직 GitHub · 칸이 비었을 때만 채움(e2e 로 답을 붙잡고 먼저 쓴 뒤 놓아 확인). remote 가 바뀌어도 칸이 차 있으면 다시 묻지 않는다 — 칸을 직접 고친다.

## 겪은 것
- 옆 패널이 열릴 때 포커스를 패널로 옮기자 `issues.spec` '느린 연결 조회 중 재열기…' 가 12번 중 2번 실패(origin/main 12/12 통과, 포커스 effect 를 빼면 16/16). 계측해 보니 시험이 '연결 목록 다시 읽기' 가 켜진 것을 보고 처리기를 바꾼 뒤에야 패널의 첫 읽기 effect 가 돌아, 첫 읽기가 붙잡힌 처리기로 들어갔다. 패널 첫 화면은 읽기 전에 그려지므로 켜진 단추는 '첫 읽기가 끝났다' 는 뜻이 아니다 → 시험을 고침(바꾼 처리기를 거친 읽기가 한 번 끝난 뒤에 붙잡기를 켬, 24/24). `useLayoutEffect` 로 앞당기는 안은 `useSyncExternalStore` 가 마운트 뒤 effect 에서 구독해 첫 화면을 바꾸지 못해 버렸다.
- preload API 를 더하면 `window.spec` '보안 기본값' 의 키 목록을 같이 고친다 — 56c 에서 `issues.repo` 를 빠뜨려 전체 검사에서 드러났다(50단계에도 같은 일).

## 계획과 다르게 한 것
- 탭 이름이 '…대화' 로 바뀌는 것은 27단계 결정이라 그대로.
- 모든 출력 찾기의 '찾을 곳' 줄은 머리가 아니라 아래에 — 위에 두면 Tab 순환 시험(uiux-polish)의 첫 칸이 바뀐다.
- 찾기 기본 범위는 바꾸지 않음(계획대로) · 낱말만 맞춤.
- main 쪽 메시지의 '원격' · 'checkout' 도 바꿈(화면에 그대로 보여서).
- 도구 줄 단추 높이를 `--row-h` 로 맞춤(글꼴에 따라 35px 이 되어 한 줄 검사가 흔들림) · 대화 입력칸 줄 간격 1.45(가독성 규칙).
- ⌘P 로 막힌 일감 도구를 고르면 토스트로 이유를 보인다(계획엔 title · 메뉴 머리만).
- 찾기를 그냥 열 때는 다른 찾기를 닫지 않는다 — '찾을 곳' 으로 바꿀 때만 닫는다.
- 4 의 'keys.spec unkeyed 목록 갱신' 은 필요 없었다 — 앱 메뉴는 키 있는 명령과 정한 목록만 싣는다.
- 7 의 e2e 는 패널에서 새로 만든 워크트리가 아니라 미리 만든 워크트리 둘로 확인(둘 중 하나는 목록 첫째가 아니어야 고른 값 반영을 가린다).
- 7 의 대상 거르기는 계획의 '기본 · bare 제외' 가 아니라 '일감 폴더 자신 · bare · 복구 필요 · git 폴더 제외'(리뷰), 목록은 `worktrees.list` 대신 새 `worktrees.targets`(리뷰 — list 는 워크트리마다 git status).
- 8 의 '키마다 한 번' 은 '칸이 비었을 때 열 때 · GitHub 로 바꿀 때, 겹치지 않게' 로(리뷰 — 빈 답 · 실패 뒤 다시 묻지 못했다).
- `issues.spec` 의 기존 시험 하나를 고침(위 '겪은 것') · PopupMenu(56 전부터 있던 공용 메뉴)에 '고를 항목이 없으면 메뉴에 포커스' 를 더함(UI/UX).

## 미검증
- 실제 GitHub(gh) · Jira 계정으로 PR 카드 · 이슈 조회 — 가짜 gh 로만.
- 이슈 저장소를 빈 답 · 실패 뒤 다시 묻는 것은 시험 없음(GitHub 로 돌아올 때 다시 묻는 것만 e2e).

- 첫 실행 안내에서 새 도구 줄을 처음 보는 흐름 · VoiceOver · 200% 확대.
