# 49 — 전체 점검에서 재현한 다섯 버그 수정

대상: `stage-44-48-orca-workflow`. 사용자 버그 수정·자율 진행·feature push 승인에 따라 진행. main 병합·출시·실제 데이터 변경은 제외한다.

## 계획

1. 손상된 이슈 기록으로 전체 앱 시작이 중단되는 문제: 생성자는 오류를 보관하고 모든 이슈 API를 차단한다. 원본은 그대로 보존하며 빈 기록으로 덮어쓰지 않는다. verify: 손상 JSON/형식 오류 단위 시험과 임시 데이터 앱 시작 시험.
2. browser navigate 실패를 CLI 성공으로 반환하는 문제: 수동 화면의 오류 상태를 유지하고 자동화 진입점은 오류를 반환한다. verify: 닫힌 loopback 포트 exit 1, 정상 주소로 다시 시도 exit 0.
3. 삭제한 연결 일감 재생성: 완료 영수증의 대상 삭제가 확인된 경우만 고정 오류 코드로 알리고 UI가 해당 요청 번호를 해제한다. verify: 같은 설정 재시도에서 기존 번호→삭제 확인→새 번호로 복구. 결과를 모를 때와 네트워크 오류는 기존 번호를 유지한다. 이중 입력은 busy와 동일 요청 번호로 차단한다. 취소·뒤로는 확인창만 닫고 기존 일감·checkout·초안을 보존한다. 삭제되기 전 성공 응답 유실은 동일 영수증으로 복구한다. 외부 이슈 상태는 자동 변경하지 않는다.
4. 원격 Git의 staged diff 누락: index와 작업 폴더 diff를 각각 읽어 비어 있지 않은 부분을 구분해 반환한다. verify: unborn·staged-only·mixed·unstaged-only 실제 임시 Git 저장소.
5. 리뷰 댓글의 무효 서명 고착: 새 diff 스냅샷을 받으면 이전 스냅샷에 대한 실패 표시를 해제한다. 실제 파일 서명 검사와 첨부 직전 재검증은 유지한다. verify: 변경→첨부 거절→원래 diff 복구→새로 읽기→첨부 성공.

## 실행과 검증

재현 시험 Red → 최소 수정 Green → 원래 버그로 되돌리는 변이 5개 → 전체 타입·경계·단위·e2e → 코드/실제 화면 리뷰 → GC 진단 → 문서·커밋·feature push.
앱 종료·창 닫기·새로 고침·렌더러 충돌은 기존 셸/저장 생명주기를 변경하지 않는다. 화면 초안은 기존 메모리 수명만 유지한다. 늦은 비동기 응답은 기존 generation/busy 경계를 유지하고 삭제된 대상은 main에서 다시 확인한다.
원격 서버·GitHub 이슈 시험은 임시 로컬 서버와 가짜 gh만 사용한다. 쓰기 실패/응답 유실에는 같은 요청 번호로 재확인하며 자동 새 요청을 만들지 않는다. 사용자 계정·운영 서버·실제 데이터는 사용하지 않는다.

## 코드·UI 리뷰

이슈 기록 손상은 읽기·설정·조회·준비·PR·닫기 전부 차단하며 외부 gh와 일감 생성 호출이 없고 원본 바이트가 보존됨을 확인했다. 디스크 쓰기 실패는 영구 손상 상태로 취급하지 않아 기존 복구 후 재시도를 유지한다. 삭제 확인만 요청 번호를 해제하고, 성공 응답을 유실한 다음 시도는 같은 번호를 사용해 중복을 만들지 않는다. 기존 checkout과 영수증은 자동 삭제하지 않는다.

원격 Git은 최초 커밋 전에도 staged diff가 보이며 같은 파일의 index/working 변경은 제목으로 구별한다. 원격 서버/IPC 형태는 바꾸지 않는다. 브라우저 수동 탐색의 화면 오류는 유지하고 CLI만 실패 종료로 바꾼다. 해당 진입점은 native CLI e2e로 검사한다(네이티브 WebContents를 가짜 구현으로 대체하지 않음).

리뷰 댓글은 새 스냅샷에서 무효 표시를 초기화해도 파일 서명과 첨부 직전 디스크 재검증을 모두 유지한다. 자동 대화 전송은 없다. 실제 화면을 열어 복구 후 잘못 남은 경고도 발견해 새 diff를 받으면 함께 지우도록 수정했다. 전체 검사에서 생성된 최종 캡처도 직접 열어 경고 제거·오류 안내·동작 복구를 확인했다: `/tmp/taskminal-49-issue-retry.png`, `/tmp/taskminal-49-review-restored.png`. 기존 모달/레이블/alert·status 구조를 유지하고 새 컴포넌트·레이아웃은 만들지 않았다. VoiceOver·Retina·실제 IME·Windows/Linux GUI는 미검증이다.

## GC 회고

`harness-gc` 읽기 전용 진단 `/tmp/taskminal-49-gc.json`: eden72/survivor28/cold12/promoted6, 승격 후보 r89439e, 병합 후보0, 규칙 감사17. Electron 아키텍처/시험 규칙은 출처가 있고 도구화 후보가 없었다. 후보 r89439e의 원래 회귀 자체를 검사하라는 요구는 이번 재현 Red와 변이5개로 실행했다. 전역 문장 추가나 자동 승격은 하지 않았다. rd0536c의 승격 후 과거 재발11회는 이번 사건이 아니며 새 기록으로 세지 않는다.

검증 중 기존 원격 큐 시험이 Promise reject를 뒤늦게 처리해 unhandled rejection을 내는 것을 확인했다. 큐를 풀기 전에 세 reject 기대를 모두 연결해 실제 경계 검사는 유지하면서 비결정적인 실패를 없앴다. 화면 검토에서 발견한 오래된 경고는 위 복구 e2e의 경고 제거 단정으로 고정했다. 새 학습 문장 대신 회귀 시험으로 도구화했다.

모델은 현재 기본값을 유지하고 공유 UI/API 변경이 겹치는 다섯 버그를 단일 에이전트가 처리했다. 더 작은 모델로 위임하는 대안은 경계 상태·IPC 재현 맥락 복제와 통합 비용 때문에 적용하지 않았다. 총 토큰·비용은 제공되지 않아 미측정이며 절감률을 주장하지 않는다. 일부 묶음 읽기가 잘려 이후 필요한 범위만 읽도록 줄였다. 전체 검사는 변경 후 한 번 실행하고, 변이는 관련 시험만 실행해 중복을 줄였다.

부수 요청: 리뷰 감시는 보이는 pane에만 등록하며 inFlight/again으로 겹친 읽기를 직렬화한다. 기존 두 pane·숨긴 pane의 늦은 첨부 e2e를 함께 실행한다.
처음 한 번만 읽는 값: 이슈 journal 손상 상태는 시작 시 고정해 쓰기를 차단하며 파일 복구 후 앱 재시작으로 다시 읽는다. 리뷰 목록은 창 focus로 새로 읽어 서명 복구를 시험한다.

가짜와 실제 분기 대조: gh fixture는 목록·상세·빈 다음 페이지·명시적 닫기를 제공한다. 권한 거절·네트워크 단절·한도는 실제 GitHub/Linear 계정과 **실제 대조 안 함**(계정을 변경하지 않는 범위). 해당 거절은 기존 번호 보존으로 처리한다. 실제 프로그램인 Git은 unborn/staged/working/mixed를 직접 실행했고, Chromium은 실제 닫힌 포트와 정상 HTTP 서버로 대조했다. 이슈 IPC의 완료 후 응답 유실은 실제 앱 handler에서 재현했다.
