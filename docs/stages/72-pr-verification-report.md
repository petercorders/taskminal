# 72단계 — 하네스에서 PR 검증 리포트 만들기

Taskminal 작업 트리에서 다음 명령을 실행하고 GitHub PR 패널의 **검증 근거**에서 생성된 JSON을 연다. 저장소, PR 번호, 인수 조건, 출력 경로를 바꿔 쓴다.

```sh
FULL_CHECK_NO_E2E=1 npm run verify:pr -- --repo owner/repo --pr 24 --criterion '전체 회귀 검사' --output /tmp/pr-24-verification.json
```

이 명령은 개발 환경에 설치된 Electron 하네스의 `full-check.sh`를 실행한다. `FULL_CHECK_NO_E2E=1`이면 타입·아키텍처 경계·Vitest까지 실행한다. 기존 하네스 종료 상태는 성공 0, 실패 1, 재실행에서만 통과 3, E2E 미실행 4다. 리포트와 명령에 같은 값을 남긴다. 전체 검사 결과가 한 줄에 들어가므로 조건 충족 여부는 리뷰어가 판단한다.

작업 트리가 깨끗한 상태로 시작해 끝까지 유지하면 검사 전후의 전체 커밋 SHA를 기록한다. Git 상태를 읽지 못했거나 추적·미추적 변경이 있으면 그 시점의 SHA를 `null`로 둔다. 두 SHA가 다르면 기존 PR 패널에 검증 대상 커밋 미확인으로 표시된다. 작업 트리 상태는 검사 전후 두 번을 관측한 값이다. Git 무시 파일과 두 관측 사이에 생겼다가 복구된 변경은 알 수 없다.

출력은 쓰기 가능한 디렉터리 안의 새 파일을 고른다. 예시는 작업 트리 밖을 사용한다. 같은 경로의 기존 파일은 보존하며 다시 실행할 때는 새 파일명을 지정한다. 사용법 또는 실행 오류와 성공한 검사 뒤 리포트 생성 실패는 종료 코드 2로 알린다. 검사가 이미 0 이외의 코드로 끝났다면 파일 생성 실패가 있어도 검사 코드를 돌려준다. 검사 도중 시그널로 중단되거나 예상 밖 코드로 끝나면 완성 리포트를 만들지 않는다. 원본 검사 로그는 하네스가 터미널에 알려 주는 별도 임시 파일에 남는다.

## 확인 방법

- CLI와 파일 게시 계약은 `scripts/pr-verification.mjs`, PR 패널의 파일 파서는 `src/shared/pr-verification.ts`에 있다.
- `tests/unit/pr-verification-report.test.ts`는 임시 Git 저장소와 종료 상태를 제어하는 셸로 0·1·3·4, 생략 환경 변수 전달, Git 상태 변화와 조회 실패, 파일 충돌과 중단을 확인한다. 생성한 JSON을 실제 PR 패널 파서로도 읽는다.
- 사용성 실험에서 제안한 작성 시간 비교는 이번 개발에서 측정하지 않았다.

## 검증 결과

- 실제 `npm run verify:pr`로 타입 검사·아키텍처 경계·단위 140파일 1,729개를 통과했다. `FULL_CHECK_NO_E2E=1`을 사용해 E2E를 생략했으며 CLI와 JSON의 종료 값은 모두 4였다. 미커밋 변경이 있는 실제 작업 트리에서 시작·종료 SHA가 모두 `null`임을 확인했다. 깨끗한 상태의 기록은 임시 Git 저장소에서 확인했다.
- 시작 작업 트리 확인, 종료 커밋 재확인, 종료 코드 기록, 덮어쓰기 방지, 중단 상태 전달의 변이 5개를 모두 검출했다.
- 코드 리뷰에서 기존 파서 호환성, Git 상태 확인 실패, 파일 충돌 시 원본 보존, 종료 상태 우선순위를 검토했다. 검증은 macOS 터미널에서 진행했다.
