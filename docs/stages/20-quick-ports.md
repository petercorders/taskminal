### 실행 경로 (빠른 명령)
- `current`: 그 일감의 활성 pane 이 셸 통합이 있고(`integratedPanes`) 바쁘지 않으면 `pty.write(cmd + '\r')`. 바쁘거나 통합이 없으면 **새 탭**에서(넣지 않는다) + 알림.
- `newTab` · `splitRight` · `splitDown`: 새 pane 의 `pendingCommand`(셸이 뜬 뒤 한 번, 13단계 길) — 폴더는 일감 폴더 기준 `cwd`.
- `insert`: 활성 pane 에 `terminals.insert`(19단계 `safeToInsert`) — 실패면 알림.
- 실행한 단추 → `runs[단추 id] = { paneId, sentAt }`(런타임). 상태는 그 pane 활동에서: `startedAt ≥ sentAt` 이고 busy 면 ● 경과, `endedAt ≥ sentAt` 면 ✓/✗ 코드, 통합이 없는 pane 이면 '상태 모름'.

### 조사 주기 (포트)
- 대상 pane: 마운트된 pane 중 **'통합이 있고 바쁘지 않음' 이 아닌 것**(실행 중 · 통합 없음 · 지킴이에 다시 붙어 아직 신호 없음). 대상이 없으면 조사하지 않는다. 조사 비용은 pane 수와 상관없이 ps + lsof 한 번.
- 주기: 창에 포커스가 있으면 3초, 없으면 15초(`TASKMINAL_PORT_POLL_MS` 로 시험이 줄인다). 창이 숨으면(`document.hidden`) 멈춘다.
- ⑧ 부수 요청: **한 번에 하나** — 앞 조사가 안 끝났으면 이번 주기는 건너뛴다(쌓이지 않는다). 안 보일 때(hidden)는 돌지 않는다.
- ⑦ 늦게 도착하는 옛 응답: 요청 번호(세대)를 붙이고, 응답이 왔을 때 최신 번호가 아니거나 그 사이 pane 이 닫혔으면 그 pane 결과는 버린다. 끄기 · 숨기기 뒤 이미 떠난 조사가 숨긴 포트를 되살리지 않게 숨김은 그리기 때 거른다(응답에 넣지 않음).
- ⑨ 처음 한 번만 읽는 값: 숨긴 포트 · 첫 알림 봄은 설정에서 **그릴 때마다** 읽는다(조사 시작 때 떠 두지 않는다). 주기 값(appInfo)만 처음 한 번 — 앱 실행 중 바뀌지 않는다.
- 실패(시간 초과 · lsof 없음): 결과 없음 + "포트 확인 못 함" 한 번, 다음 주기에 다시 시도. 이전 포트는 그대로 둔다(한 번 실패로 칩이 사라졌다 생기지 않게).

### 상태가 사라지는 경우 (고른 뒤 나중에 실행)
- 확인 창 · 편집 창 · 메뉴는 **단추 id · 일감 id** 만 들고, 누르는 순간 다시 찾는다. 그 사이 단추 · 일감이 지워졌으면 아무 일 없이 닫고 알림 "그 단추는 지워졌어요".
- 편집 창은 연 순간의 값을 떠 둔다(그 사이 다른 곳에서 바뀌어도 고치던 글이 바뀌지 않음). 저장할 때 그 단추가 없으면 새로 더하지 않고 알림.
- 포트 끄기 확인: pid · 포트 · paneId 를 연 순간에 떠 두고, main 이 끄기 직전에 다시 조사해 같은 pane 자손의 같은 포트일 때만 끈다. 아니면 "이미 꺼졌어요".
- 앱 종료 4경로(앱 종료 · 창 닫기 · 새로 고침 · 렌더러 충돌): 런타임 상태(단추 상태 · 포트)는 버린다 · 빠른 명령 자체는 상태 파일에 저장되어 남는다 · 보낸 명령은 셸 지킴이의 셸에서 계속 돈다.

### plan-check 칸
- ① 결과를 모를 때: 셸에 보낸 명령이 시작 신호(C)를 안 보내면(통합 없음 · bash) '상태 모름'. 포트 끄기 뒤 결과는 main 답(꺼짐 · 이미 꺼짐 · 실패)으로 알림, 칩은 다음 조사로 맞춘다.
- ② 다시 시도: 실패 단추를 다시 누르면 같은 자리에서 다시 실행(실패 표시는 성공 때 사라짐). 조사 실패는 다음 주기가 다시 시도.
- ③ 이중 입력: 실행 중인 단추를 다시 누르면 — `current` 는 바쁜 pane 이라 새 탭(끼워 넣지 않음), 키 반복(⌥1 누르고 있기)은 한 번만(`e.repeat` 무시). 확인 창 ↩ 두 번은 첫 번에 닫혀 한 번만. 끄기 버튼 두 번은 첫 번에 닫힘.
- ④ 취소 · 뒤로 · 닫기: 확인 · 편집 창 Esc · 취소는 아무것도 안 함. 지우기 · 숨기기는 알림 5초 안 되돌리기(⌘Z).

변이 확인(핵심 줄 15개): 처음 판 — 잡음 11 · 못 잡음 1 · 판정 불가 3(늘 같은 조건으로 바꿔 컴파일이 깨짐 → 값을 바꾸는 변이로 다시). 못 잡은 것은 `killPort` 의 pid 검사 — 시험이 없는 pid(`pid + 999999`)를 줘서 `process.kill` 이 던져 'gone' 이 됐다 → 살아 있는 형제 `sleep` pid 로 바꾸고 sleep 이 살아 있는지까지 본다. 다시 돌려 15개 모두 잡음.

전체 검사: 단위 665 · e2e 155 통과(종료 코드 0, 흔들림 없음). 리뷰 고침 뒤 다시: 단위 669 · e2e 157 통과(종료 코드 0, 흔들림 없음). 스크린샷 `quick-bar` · `ports-chip` · `ports-conflict` · `ports-closed` 직접 확인.

계획과 다르게 한 것
- 바빠서 새 탭으로 간 안내는 터미널 아래 줄이 아니라 알림(Toast) — 새 탭으로 화면이 바뀌어 아래 줄은 보이지 않는다.
- 처음 포트 알림은 [열기] 단추 없이 글만 — 알림 단추는 ⌘Z(되돌리기 자리)를 받아 '열기' 가 ⌘Z 에 묶인다. 칩을 누르라고 안내.
- 포트 겹침 막대는 pane 아래가 아니라 탭 줄 바로 아래 — 아래에 두면 알림과 겹쳤다(스크린샷에서 드러남).
- 사이드바 칩은 보기만(누르기 · 메뉴 없음) — 행 클릭(일감 가기)과 겹친다. 여는 것은 탭 칩 · ⌘P.
- 실행 전 확인 창의 기본 포커스는 [실행](보드대로), ↩ 는 창 안 어디서든 한 번 실행. 포트 끄기 확인은 [취소] 가 기본.
- 조사 대상 pane: 계획은 '실행 중 pane' — 실제는 바쁨 · 셸 통합 없음 · 열린 칩이 있는 pane(통합 없는 셸은 실행 중인지 모르고, 열린 칩은 닫힘을 봐야 해서).
- 같은 pane 의 다음 명령이 앞 단추의 ✓ 를 ✗ 로 바꾸는 문제(스크린샷에서 드러남) → `advanceRun` 으로 단추마다 시작 · 끝을 처음 본 순간에 굳힌다. 실패 말풍선은 그 실행의 첫 기록 줄.
- 템플릿 JSON 편집이 `quickCommands` 를 지우던 것(`replaceTemplate` 이 칸을 골라 담음) → 펼쳐 담기. 템플릿 편집기에 빠른 명령 칸은 만들지 않았다(일감에서 만들고 '템플릿으로 저장' 이 담는다).
- 시험: 계획 e2e 6번('확인 창이 열린 동안 단추가 지워짐')은 만들지 않았다 — 모달 아래 단추 메뉴를 열 수 없어 그 상태를 만들 수 없다. 대신 실행 때 id 로 단추를 다시 찾는다(코드). ⌥숫자는 합성 키(`e.code`)로만 확인 — 한글 입력기 켠 상태는 미확인.
- 하지 않음(위 '하지 않는 것' 그대로): 전체 보기 카드 · http 응답 확인 · docker/원격 포트 · 끌어서 순서 · 터미널 우클릭 저장.
