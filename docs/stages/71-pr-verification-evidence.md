# 71단계 — PR의 현재 커밋에서 확인한 것 보기

GitHub PR·push 패널의 **검증 근거**에서 로컬 검사 보고서를 열 수 있다. 보고서에 적힌 인수 조건, 검사 이름, 종료 상태를 보여 주고, 검사 시작·종료 커밋을 화면에서 읽은 PR head와 비교한다.

- 커밋이 바뀌면 **이전 커밋 · 다시 확인**을 표시한다. PR 상태를 읽는 중이거나 읽기에 실패하면 현재 커밋을 확인 중이거나 확인하지 못했다고 표시한다.
- 검사 시작·종료 커밋이 다르거나 하나라도 없으면 **검사 대상 커밋 미확인**을 표시한다.
- 검증 결과는 가져온 파일의 기록이다. 실행 환경이나 인수 조건 충족 여부는 리뷰어가 판단한다. 앱 안에서는 검사 명령을 실행하지 않는다. 파일 내용은 패널을 닫거나 일감을 바꾸면 사라진다.

## 보고서 만들기

검사 직전과 직후의 전체 `git rev-parse HEAD` 출력을 기록한다. 변경이 없는 작업 트리에서 검사하고, 시험 종류와 종료 상태를 인수 조건에 연결한다. 예시의 반복 문자 SHA, 저장소, PR 번호를 실제 값으로 바꾼다. 과거 기록의 검사 대상 커밋을 확인할 수 없으면 해당 SHA를 `null`로 둔다.

```json
{
  "version": 1,
  "repository": "owner/repo",
  "pullRequest": 24,
  "startSha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "endSha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "entries": [
    {
      "criterion": "좁은 창에서 가져오기 버튼이 겹치지 않는다",
      "check": "tests/e2e/import-repo.spec.ts",
      "exitCode": 0
    },
    {
      "criterion": "정리 도중 이름이 바뀌어도 대상 일감을 잘못 처리하지 않는다",
      "check": "tests/e2e/worktree-cleanup.spec.ts",
      "exitCode": null
    }
  ]
}
```

UTF-8 JSON 64KiB 이하, 조건 1~50개. 조건은 400자, 검사 이름은 200자까지 쓴다. 종료 코드는 하네스 기준으로 정규화한다. 0은 통과, 3은 불안정, 4는 e2e 미실행, 그 밖의 양의 정수(255 이하)는 실패다. 아직 검사하지 않았으면 `null`을 쓴다.

## 구현과 확인

- `src/shared/pr-verification.ts`에서 형식, 대상 PR, SHA와 검사 결과를 검증한다. `src/renderer/PrVerification.tsx`는 사용자가 고른 파일만 읽고, `src/renderer/GitWorkflow.tsx`는 기존 PR 조회의 최신 상태를 연결한다.
- GitHub의 최근 PR #24·#25에는 검사 실행이 없어 기존 로컬 결과를 첫 근거로 택했다. Actions 결과 연결과 사용성 비교는 별도 검토다.
- 최종 검증은 타입 검사, 아키텍처 경계, 단위 139파일·1,715개 통과다. `FULL_CHECK_NO_E2E=1`로 종료 코드 4를 확인했다. 변이 4개 모두 검출했다. 검사 범위는 다른 PR 보고서, UTF-8 크기 제한, 시작·종료 SHA 불일치와 이전 커밋 표시다.
- e2e 제외 지시가 도착하기 전에 시작한 6건은 이미 종료된 상태였다. 이번에 추가한 e2e 2건과 모의 GitHub 변경은 커밋에서 뺐고, 이후 e2e는 실행하지 않았다. 이전 캡처에서 라이트의 열기·결과와 좁은 다크 창의 200% 확대를 확인했다. 좁은 창의 전체 콘텐츠와 실제 보조기술 확인은 남아 있다.
- 코드 리뷰에서 파일 접근 범위, 읽기 실패 시 이전 보고서 유지, PR 변경 시 보고서 격리, 조회 실패 시 현재 커밋 표시 제거를 검토했다. 커밋 일치는 마지막 PR 조회 기준임을 화면에 적었다.
