# 66 — 알림 받은편지함 (지난 알림 · 안 읽음 유지)

사용자 2026-11-19 "계속 진행해줘" — `docs/ideas/orca-next-five-v5.md` 5번 대안(v4 의 9)을 자율 진행 지시대로 추천안으로 골랐다. 쌓인 e2e 를 돌리는 쪽은 "e2e 하지 마" 지시가 아직 유효해 고르지 않았다.
**사용자 지시: e2e 는 돌리지도 새로 쓰지도 않고 앱도 띄우지 않는다** — 검증은 typecheck · 경계 · 간격 · 단위 · 변이까지다.

## 문제
알림(입력 기다림 · 끝남 · 실패 · 셸 닫힘)은 macOS 배너로 한 번 뜨고 사라진다. 전체 보기 · 사이드바 '확인 필요' 는 *지금* 상태만 보이고, 확인하거나 앱을 다시 열면 지난 일은 남지 않는다. 자리를 비웠다 돌아오면 그 사이 무엇이 끝났는지 한 곳에서 볼 수 없다.

## 만든 것
- **기록**: 알림을 내는 자리(`App.tsx` 의 `deliver`)에서, 그 pane 을 보고 있지 않으면 한 줄을 남긴다. 줄에는 종류 · 일감 · pane · 제목 · 본문(배너와 같은 가린 글)이 들어간다. 알림 · 소리를 꺼 둔 종류도 남긴다 — 설정은 방해만 끈다. 보고 있던 pane 의 알림은 남기지 않는다.
- **저장**: main `InboxStore` 가 `<userData>/inbox.json`(0600)에 쓴다. 쓰기 전에 다시 가리고(renderer 를 믿지 않는다), 300개 · 30일까지 둔다. 늘 전체를 임시 파일 → rename 으로 쓰고, 일은 큐로 하나씩 한다. 깨진 파일은 `.bak` 으로 옮기고 빈 목록으로 시작한다(받은편지함은 지난 알림의 사본이라 앱을 멈추지 않는다 — `AtomicJournal` 은 쓰지 않았다).
- **읽음**: 그 pane 을 보면 그 시각까지의 그 pane 알림이 읽음이 된다. 바뀐 것이 없으면 main 에 보내지 않는다. 받은편지함 줄을 누르거나 '모두 읽음' 을 눌러도 읽음이 된다.
- **화면**: 전체 보기 맨 위 **'지난 알림'**.
  - 줄마다 종류 아이콘 · 제목 · 안 읽음 · 본문 · 일감 · 몇 분 전.
  - 누르면 그 순간 pane 을 다시 찾아 연다. 닫혔거나 보관했으면 열지 않고 글로 알린다(알림은 읽음으로).
  - 처음에는 8줄, 더 있으면 '모두 보기'. '모두 읽음' · '비우기…'(확인 창, body 에 그림).
  - 사이드바(좁은 창 포함) '전체 보기' 단추에 '· 알림 N'(안 읽은 수).
- 일감을 지우면(되돌리기를 놓친 뒤) 그 일감의 알림도 지운다.

## 여러 단계 · 기다림
- renderer 가 가진 목록이 기준이고 main 에는 바뀐 것만 보낸다. 쓰기 답을 기다리지 않고, 답으로 화면을 바꾸지 않는다. 쓰기 실패는 콘솔 · 오류 기록에만 남고, 다음 쓰기가 전체를 다시 쓴다.
- 처음 한 번 읽는 동안 생긴 알림 · 읽음 · 지운 일감 · 비우기는 읽어 온 목록에 다시 적용한다 — 늦게 온 읽기 답이 덮지 않는다(시험: 읽기를 gate 로 늦춤).
- 같은 id 는 화면 · 파일 모두 한 줄이다. 파일은 처음 것의 본문을 남긴다.
- 읽음은 안 읽음으로 돌아가지 않는다(합칠 때 어느 쪽이든 읽었으면 읽음).
- 전체 보기 안의 확인 창이 받은 Esc 로 전체 보기까지 닫히지 않게, 전체 보기의 Esc 는 `defaultPrevented` 면 무시한다.

## 검증
- typecheck · 경계 · 간격 · 단위 전체 통과(수는 커밋 메시지).
- 변이 12개 — 처음 10개 중 3개를 못 잡았다.
  - '30일 넘은 것 버림' 은 시험이 300개 상한에 기대 날짜만으로 버리는지 못 봤다. 단정을 더해 잡았다.
  - '볼 때마다 쓰지 않음' · '파일의 같은 id 막기' 는 다른 줄(`read` 의 바뀐 것 없음 검사 · `mergeInbox`)이 이미 같은 일을 했다. 중복 코드라 지웠다.
  - 다시 돌린 2개(30일 · 같은 id 는 앞 것 본문)는 모두 잡았다.

## 계획과 다르게 한 것
- 계획의 `InboxRead` 외에 줄 하나로 열기 전에 읽음 표시를 한다(누르면 열리지 않아도 읽음).
- '볼 때 안 읽은 것이 있을 때만 보낸다' 를 `viewed` 의 따로 검사가 아니라 `read` 의 '바뀐 것 없음' 으로 지킨다(변이 확인에서 중복으로 드러남).
- 계획에 없던 것: 전체 보기 Esc 의 `defaultPrevented` 검사(비우기 확인 창 때문에 필요).

## 범위 밖 · 안 한 것
- 마지막 응답 한 줄(대화 pane 의 답 글): 알림 본문(일감 · 명령 · 에이전트 상태 · 메시지)만 남긴다.
- Claude 한도 막대 알림: pane 이 없어 넣지 않았다.
- 설정 › 개인정보 '모두 지우기' 묶음에 넣지 않았다 — 전체 보기의 '비우기…' 가 지운다.

## 미검증
- `deliver` 가 보고 있지 않은 pane 만 남기는지 · 그 pane 을 보면 읽음이 되는지(App 안의 연결 — 단위 시험이 닿지 않는다).
- 전체 보기 '지난 알림' 의 모양 · 좁은 창 · 키보드 · 화면 읽기 프로그램.
- 실제 macOS 알림과 받은편지함 줄이 같은 글인지.

## 돌려야 할 e2e (사용자 지시로 이번에는 돌리지도 쓰지도 않음)
- 다른 일감을 보는 동안 셸 명령이 실패 → 전체 보기 '지난 알림' 에 '명령이 실패했습니다' 줄 · 사이드바 '전체 보기 · 알림 1' → 줄을 누르면 그 pane · 안 읽음이 사라짐.
- 보고 있는 pane 의 알림은 남지 않는다.
- 앱을 다시 띄워도(같은 임시 데이터) 줄이 남는다 · 읽음도 남는다.
- '비우기…' → 확인 창의 Esc 는 확인 창만 닫는다 · 확인하면 목록이 빈다.
- 일감을 지우고 되돌리기를 놓치면 그 일감의 줄이 사라진다.
