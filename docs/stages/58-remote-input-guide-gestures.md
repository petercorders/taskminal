## 요청 칸 (58a — 원격 터미널 입력)
- 결과를 모를 때: 쓰기 응답이 유실되면 지금처럼 입력을 멈추고 같은 묶음 · 같은 번호를 쥔다.
- 다시 시도: 보낸 묶음을 그대로 다시 보낸다. 서버는 끝난 번호면 저장된 결과를 돌려주고 pty 에 다시 쓰지 않는다.
- 한계: 그 터미널에서 그 뒤로 100번 넘게 쓰기가 끝났으면(입력이 멈춘 그 연결이 아니라 같은 터미널에 붙은 다른 연결이 친 경우) 옛 번호는 새 요청으로 실행된다. 다른 터미널 · 다른 종류의 요청은 영향을 주지 않는다.
- 이중 입력: 보내는 중에 친 글자는 다음 묶음으로 — 보낸 묶음에 섞지 않는다.
- 안 끝난 기록: 실패 · 중단된 요청의 번호는 다시 실행되지 않고 거절된다(지금 동작). 1,000개를 넘으면 오래된 것부터 지운다.

## 돌려야 할 e2e (돌리지 않음 — 다음에 e2e 를 돌릴 때 먼저 볼 것)
- 원격: `remote-terminal-depth.spec` 전체 — `RemoteTerminal` 이 새 큐를 쓰는 연결(단위로 못 봄). 지연을 넣어 '쌓인 글자가 한 요청으로 · 순서 그대로' 를 보는 시험은 아직 없다(초안만 있었고 넣지 않았다).
- 대화 인자: `chat.spec:127-143 · 275 · 291-294 · 317-319` · `agent-sessions.spec:167 · 236` · `schedules.spec:25` · `workflows.spec:20 · 36 · 72` · `workflow-parallel.spec:115-120` — 가짜 claude 의 argv 를 본다(안내 인자가 끝에 붙는다).
- 설정 화면: `settings.spec:69 · 75 · 119` · `settings-reflow.spec:7 · 37` · `layout-align.spec:102-128` · `responsive.spec:66` — 일반에 '대화' 묶음 · 터미널에 행 하나가 늘었다.
- 탭 · 터미널: `tabs.spec` 전체(탭에 draggable · 탭 화면 그리는 순서) · `terminal.spec` 전체(끌어 놓기 리스너 · OSC 52 처리기) · `keys.spec:295-311`(키 없는 메뉴 항목 목록 — 두 명령을 정적으로 더했다) · `palette.spec:138` · `layout-align.spec:145 · 174` · `window.spec:41`(preload 목록 — 공유 목록이라 따라간다).

## 계획과 다르게 한 것
- 58a 기록 정리: 계획은 '끝난 기록 최근 2,000개 한 창 · 안 끝난 기록은 지우지 않음 · 기록 파일 형식 그대로' 였다. 리뷰로 세 갈래 상한과 선택 칸 `input` 으로 바꿨다.
- 58b: 설정 화면에 '대화' 묶음이 없어 일반 칸에 새로 만들었다. 작업 흐름 전용 대화도 같은 길이라 안내를 받는다. 브라우저 명령은 세 개만 줄로, 나머지는 `taskminal help`.
- 58c: preload 는 `filePath(file)` 하나씩 · 제어 글자가 든 경로는 모두 건너뜀 · 넣기는 `term.paste` · OSC 52 글도 화면 가리기를 거침 · 빈 내용은 버림(클립보드를 비우지 못하게).
- 계획에 없던 것: 탭 화면을 처음 본 순서로 그리기(탭을 옮기면 화면 노드가 옮겨져 스크롤 · 포커스가 풀리는 것을 막음) · OSC 52 를 보이는 pane · 포커스 창으로 좁힘 · 끌어 놓기의 Windows 규칙.
- 58c worker 가 '노드를 옮기면 스크롤이 풀리는지' 를 재려고 숨은 Electron 창 하나를 2~3초 띄웠다(Taskminal 앱 · Playwright 는 아님). e2e 금지 지시와 닿을 수 있어 적는다.
- worker 커밋은 파일을 골라 올렸다 — worktree 에 링크한 `node_modules` 가 `.gitignore` 의 `node_modules/` 에 걸리지 않아서.
- 실제 화면 UI/UX 리뷰는 하지 않았다(앱을 띄워야 한다).

## 미검증
- 실제 claude 가 안내를 받아 `taskminal` 명령을 제때 쓰는지 · `-p` stream-json · `--resume` 과 함께 인자가 먹는지.
- 실제 끌어 놓기 · OSC 52 가 클립보드에 닿는지 · 탭 끌기 · 메뉴/⌘P 의 두 명령 · 새 설정 행의 모양(좁은 창 포함).
- 실제 원격 서버에서 묶어 보내기 · 한도에 닿았던 서버가 풀리는지.
- Windows · fish 에서 끌어 놓은 경로.
