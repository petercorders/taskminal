# 29단계 — UI/UX와 작은 창·분할 화면 대응

2026-11-12 사용자 `harness-run ui/ux` → 앱 전체 주요 화면 선택 → 개선 계획 승인, 사이드바 폭 개선과 반응형 작업 추가 요청.
브랜치: `uiux-sidebar-polish`, 기준: main `0af1056`.

## 기준과 확인

27·28단계의 기존 컴포넌트·색·간격 토큰을 유지한다. 화면 모양과 실제 키보드 동작을 함께 확인한다.
사전 가독성·정렬 e2e 12개 통과. 임시 userData에서 주요 화면과 설정 10칸을 열고 캡처를 직접 확인했다.
자료: `test-results/readability/`, `test-results/ux-audit/`.

## 발견 사항과 변경

| 심각도 | 화면·상태 | 재현·영향 | 변경 |
|---|---|---|---|
| 높음 | 보관함 키보드 | 최근 지운 것 탭에서 Enter → 탭 전환 대신 보관 일감 되살림. 체크박스 Space도 목록 선택을 잘못 바꿈 | 버튼·탭·체크박스의 기본 동작 보존 |
| 높음 | 변경 검토, 되돌린 것 | 두 번째 되살리기 버튼 Enter → 첫 항목과 둘째 항목 모두 실행. 수정 전 시험에서 두 파일 모두 복원됨 | 버튼 Enter와 목록 Enter 분리, 버튼에서도 Esc 돌아가기 유지 |
| 중간 | 작은 창·긴 모달 | 640×400 새 일감의 아래 끝 627px, 긴 보관함은 900×600에서도 아래 끝 634px | 모달 border-box와 공용 높이 제한·내부 스크롤, 개별 높이 재정의 제거 |
| 중간 | 보관함 긴 목록 | 방향키로 고른 항목이 화면 밖에 남음 | 선택 행 스크롤과 검색·행 감소 때 커서 보정 |
| 중간 | 모든 출력 찾기 | Tab이 범위 전환에 묶여 더 보기 버튼에 접근 불가 | Tab 포커스 순회, Control+Tab 범위 전환, 모달 안 포커스 유지 |
| 중간 | 최근 지운 것 | 백업 읽기 실패를 일감 없음으로 표시 | 읽는 중·실패·부분 실패·빈 결과 분리, 재시도와 이전 응답 무효화 |
| 중간 | 사이드바·설정 | 248px에서 긴 일감 이름이 일찍 잘리고, 작은 창의 설정 관리 행은 가로 넘침 | 일반 창 최대 288px, 중간 창 최소 248px, 800px 이하 200px. 설정 탐색에도 같은 폭 사용. 좁은 설정 내용은 줄바꿈·여백 축소 |
| 중간 | 좁은 분할 pane | 창 폭만으로는 대화·검토의 사용 가능 폭을 알 수 없음 | pane 너비 560px 이하에서 머리·입력 도구 줄바꿈, 검토 파일 목록을 diff 위로 배치 |

작은 pane에서는 대화 입력의 보조 단축키 설명과 검토의 보조 줄 선택 안내를 숨긴다. 보내기·그림·허락·셸·TUI·줄 선택·되돌리기 액션은 유지한다.
팔레트 도움말은 작은 창에서 다음 줄에 놓는다. 보관함 행의 액션도 다음 줄에 놓는다.

## 계획과 verify

1. 회귀 시험을 먼저 추가 → 옛 코드에서 잘못된 대상 복원·포커스·잘림·오류 소거를 재현.
2. 보관함·변경 검토 키 처리와 복구 읽기 상태 수정 → 버튼 대상 하나만 실행, Checkbox Space 한 번, 실패·부분 실패·재시도·탭 이탈 시험.
3. 반응형 폭·모달·설정·대화·검토 수정 → 640×400 / 900×600 / 1280×800에서 주요 컨트롤 도달, 설정 가로 넘침 없음, 모달 사방이 창 안에 있음.
4. 정확한 회귀 구조로 변이 확인 → 키 가로채기 복원·오류 소거·스크롤 제거·폭/높이 제한 제거 시 회귀 시험 실패.
5. 전체 검사와 독립 코드 리뷰 → 수정 화면 캡처 직접 확인, 주요 액션 재조작, 결과를 아래에 기록.
6. 문서 갱신·커밋. main 병합과 출시 게시 제외.

## 상태와 수명

plan-check: 서버 없음 — 로컬 상태·백업 파일과 임시 git 저장소를 다루는 Electron UI 변경이다.

- 결과를 모를 때: 백업 조회 로딩과 실패를 명확히 구분한다. 복원 결과 처리 자체는 기존 경로를 사용한다.
- 다시 시도: 최신 요청 번호만 반영하고 이미 읽힌 복원 후보는 일부 실패에도 유지한다.
- 이중 입력: 키 하나가 상위 처리·버튼 처리 양쪽을 실행하지 않는다. 조회 중 재시도 버튼은 disabled.
- 취소·뒤로: Esc와 닫기 시 백업 요청을 무효화한다. 재개방은 새 조회.
- 부수 요청: 해당 탭이 보일 때만 읽으며 폴링을 추가하지 않는다. 요청이 겹치면 이전 응답을 버린다.
- 처음 한 번만 읽는 값으로 고정하지 않는다. 재조회·일감 목록 변경에서는 최신 상태를 참조해 낡은 후보를 제외한다.
- 열린 대화상자·비동기 then 사이 대상이 사라지면 최신 id 존재 여부를 확인하는 기존 복원 경로를 유지한다.
- 앱 종료·창 닫기·새로 고침·렌더러 충돌에서 셸·저장의 기존 경로는 바꾸지 않는다. 임시 선택·포커스·조회 상태는 재시작 때 새로 만든다.
- 실제 계정·원격 접속·실제 사용자 데이터는 사용하지 않는다. 실제 IME·레티나·스크린리더 청취는 미검증.

## 시험과 캡처

- `tests/e2e/archive-ux.spec.ts`: 키보드 대상·선택 스크롤·조회 오류·부분 실패·늦은 응답.
- `tests/e2e/uiux-polish.spec.ts`: 긴 일감 이름·작은 창의 마지막 액션·검색 옵션 포커스·더 보기.
- `tests/e2e/review.spec.ts`: 두 번째 복원 버튼 Enter와 Esc.
- `tests/e2e/responsive.spec.ts`: 세 가지 창 크기, 대화·검토·설정 10칸·모달·팔레트.
- 1280px 창에서 125% UI 확대 후 일감 관리 화면의 가로 넘침도 검사한다.
- 기존 명령 기록 시험은 터미널의 접힌 줄을 이어서 명령 글자를 비교한다. 기존 가림 재검사 시험은 같은 물리 줄을 의도하므로 1400px 창을 명시한다(접힌 토큰 검사는 기존 별도 시험).
- 스크롤 선택 행의 경계는 정수 scrollTop과 소수 행 높이 차이를 고려해 1px 오차를 허용한다. 실측 차이는 0.08px였고 스크롤 제거 변이는 여전히 실패한다.
- 캡처: `test-results/uiux-*.png`, `test-results/responsive/`.

## 결과

- 회귀 변이: 9개 모두 잡음. 보관함 키·스크롤·오류 소거·요청 무효화, 검토 이중 실행, 사이드바 옛 폭, 모달 높이 제한 제거, 검색 Tab 가로채기, 보관함 옛 content-box·개별 높이 제한.
- 첫 마지막 변이는 개별 높이 제한만 되살려 새 border-box 조건에서는 안전해 실패하지 않았다. 정확한 옛 content-box와 높이 제한을 함께 복원한 변이로 다시 확인해 실패를 봤다. 다른 변이로 같은 회귀를 확인했다고 세지 않았다.
- 독립 코드 리뷰: 모달 높이 재정의·가로 넘침·버튼 Esc 회귀·좁은 대화 입력 줄을 고쳤고, 최종 리뷰에서 추가 제품 결함 없음. 문서의 숨김 안내 범위 정정도 반영.
- UI/UX: 캡처를 직접 열어 넓은 사이드바, 640px 대화·분할 검토·설정·보관함, 검색 펼치기를 확인. 키보드 순회·복원·더 보기는 실제 Playwright 입력으로 확인했다. 스크린리더 청취는 확인하지 않았다.
- 최종 전체 검사(2026-11-13): 타입·경계 통과, 단위 992개 통과, e2e 261개 통과·1개 제외, 재실행 없음. 제외는 패키지 앱 전용 시험으로 이번 개발 빌드 검사 대상이 아니다. 전체 검사 종료 코드 0, 로그 `/tmp/taskminal-uiux-final-check.log`.
- 실제 설치본·레티나 화면·실제 Claude/Codex 계정·IME 조합·스크린리더 청취는 미검증이다. UI 확대는 125%를 검사했다.

## 회고

- 진단만 수행했으며 전역 규칙은 수정하지 않았다. 사용자의 사이드바·반응형 요청은 범위 확장으로 반영했다.
- 도구 한계: retro-collect.py가 이 Codex transcript 형식을 지원하지 않아 자동 회고·토큰 집계는 미확인이다. Codex 어댑터는 별도 하네스 도구 개선 후보이며 이 앱 변경에는 포함하지 않았다.
- GC 진단: 승격 후보 r89439e(정확한 회귀 변이 확인), 승격 후 재발 rd0536c(환경 사실 검증), 병합 후보 없음, 규칙 감사 지적 없음. 이번 회귀는 실제 옛 구조 변이로 검사했으며 새로운 판단 규칙을 추가하거나 기존 규칙을 승격할 근거·사용자 선택은 없었다.
