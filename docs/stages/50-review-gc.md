# 50단계 리뷰와 GC

## 코드 리뷰

부모가 실행·경로·프로세스·journal·원격 계약을 검토하고, UI worker가 개발 도구와 workflow 변경을 별도로 읽기 검토했다.

| 발견 | 조치·검증 |
|---|---|
| 완료 실행에 단계 추가 시 같은 일감의 다른 실행과 겹칠 수 있음 | 다른 활성 실행 소유권을 검사. 완료 A→실행 B→A 추가 거절 시험 |
| JSON 필드 순서·비밀값 가림 뒤 같은 요청이 다른 내용으로 판정됨 | 순서 독립적인 명시적 필드 비교와 저장 시 동일 가림/길이 적용. 재전송 시험 |
| 승인한 파일을 실행 중 다시 읽으면 바뀐 원문이 복사될 수 있음 | 설정·파일을 하나의 서명된 스냅샷에서 사용. 복사 직전 원본 변경 시험 |
| 비동기 경로 확인 중 취소·일감 삭제 후 명령 시작 가능 | spawn 직전 동기 취소·권한 검사, 완료 전 취소 검사. 권한 철회 시험 |
| 최대 길이 로그에 재시작 안내를 추가하면 복구 저장 실패 | 가림·20,000자 제한 뒤 unknown 복구. 최대 길이 로그 시험 |
| 로그 청크 단위 가림은 나뉘어 도착하는 비밀값을 노출할 수 있음 | 명령 단위로 버퍼링·가림 후 완료 시 공개. 실행 상태와 취소는 별도로 제공 |

외부 writer가 동시에 디렉터리를 교체하는 공격에 대한 OS sandbox·openat 수준 원자성은 제공하지 않는다. 선언형 확장만 허용하고 임의 JS SDK는 이번 범위에서 제외했다. 실제 공급자 계정·Windows/Linux GUI·NAS·모바일 앱은 미검증이다.

## UI/UX — 부분 검증

- 범위: 코드 편집, 환경 준비/오류/중단/응답 유실, 확장 설치/비활성/제거, worker 질문/답변/재시도, 원격 문자 입력/resize/재접속.
- 환경: macOS arm64, 프로젝트 Electron/Chromium, 기본 어두운 테마. 1200×768 대표 캡처와 환경 도구 640×480·200% 확대. 가짜 공급자와 실제 Git·파일·PTY 사용.
- native e2e에서 키보드 편집·다중 커서·찾기/바꾸기·undo·포커스, 좁은 창의 확인/취소, 확대 상태의 확장 검사·오류 도달을 확인했다. 부모가 편집기·환경·확장·감독·원격·좁은 창·확대 캡처를 직접 열었다.
- 캡처: `/tmp/taskminal-50-code-editor.png`, `/tmp/taskminal-50-environment-preview.png`, `/tmp/taskminal-50-extensions.png`, `/tmp/taskminal-50-supervision-question.png`, `/tmp/taskminal-50-development-narrow.png`, `/tmp/taskminal-50-development-zoom.png`, `test-results/remote-terminal-depth.png`.
- 기준: 기존 프로젝트 폼·버튼/스크롤 패턴, 하네스 UI 리뷰의 키보드/확대/상태 복구 항목. 전체 대비 인증·실제 VoiceOver·IME·Retina 육안 확인·실제 참여자 사용자 테스트는 미수행이다.

## GC·실행 회고

`harness-gc` 읽기 전용 진단: eden69, survivor28, cold15, promoted6; 승격 후보 `r89439e`, 병합 후보0. 전역 규칙은 자동 변경하지 않았다. 해당 후보는 실제 회귀를 재현한 변이를 요구하는 판단이며 기존 mutation-check 도구를 사용했다. 새 규칙 문장 승격보다 이번 시험의 검출 공백을 고쳤다.

| 영역 | 관측·처리 |
|---|---|
| 판단/시험 | 원격 출력 cursor 변이가 처음에는 검출되지 않음. ANSI 전체 화면 재생이 화면 중복 검사를 숨겼다. 소비한 offset을 다음 조회에서 전진시키는 계약을 실제 IPC로 검사하도록 보강 |
| 도구 사용 | 완료 gate를 상수 false로 바꾸면 TS 좁히기가 깨져 판정 불가. 조건을 반대로 바꾼 실행 가능한 변이로 재확인 |
| 시험 수정 | 임시 폴더 realpath·IPC 배열 인자 계측·새 preload API 기대 목록을 정정. 실패 로그를 성공으로 세지 않음. Bash plan-check를 Python으로 호출한 실행 오류도 Bash로 정정 |
| 모델 선택 | 부모·worker 모두 세션 기본 모델/추론 설정 유지. 별도 모델 override 없음. 총 토큰·비용·절감률은 도구에서 제공되지 않아 미측정 |
| 멀티에이전트 | 독립 편집/도구 UI와 원격 UI를 최대2 worker에 분담. 고위험 backend·통합은 부모, 마지막 읽기 리뷰는 기존 worker 재사용. 복수 build/e2e는 슬롯을 순서대로 사용 |
| 토큰·검증 비용 | 영역별 focused 검사 후 통합 전체 검사는 한 번. 실제 결함·변이 공백을 고친 부분만 추가 검사. 전체 콘솔 대신 로그·요약 사용 |
| 추가 개선 | 실제 CLI/계정·Windows/Linux·보조기술 대조와 임의 JS 확장 권한 설계는 각각 별도 검증 범위. 이번 릴리스 완료로 주장하지 않음 |

전역 규칙 감사17개는 모두 출처가 있고 밀도 초과·새 도구화 후보가 없었다. `rd0536c`의 승격 후 과거 재발11회는 이번 사건으로 세지 않는다. 근거는 진단 JSON `/tmp/taskminal-50-gc.json`에 보존했다. 이번 결함은 프로젝트 회귀 시험으로 처리했으며 전역 엔트리 create/reinforce/promote는 적용하지 않았다.
