# 다음 다섯 가지 (여섯 번째) — 매일 쓰는 도구로 넘어오려면

일자: 2026-11-19. 상태: **조사 · 결정 기록, 구현 승인 아님**(`/harness-run electron idea 5가지 진행해줘`).
기준: Taskminal `origin/main` 0853469(66단계까지) · Orca 설치본 1.4.257 CLI · Orca 릴리스 1.4.258~1.4.263(2026-11-13~18) · 비슷한 도구들의 최근 릴리스 노트(조사일 2026-11-19, 출처는 표에).
요청에 주제가 없어, 앞선 다섯 번의 'Orca 비교' 를 넓혀 **"사용자가 Taskminal 을 매일 쓰는 도구로 넘어오려면 다음에 무엇이 필요한가"** 로 물었다. 앞선 기록(v1~v5)과 31~66단계에서 만든 것은 다시 고르지 않는다.
공개 저장소라 사용자 환경의 관찰값은 일반화해 적는다. **e2e 는 돌리지 않았다**(사용자 지시가 이어진다) — 조사는 코드 읽기 · 읽기 전용 명령 · 공개 웹 문서뿐이다. Orca 항목은 `gh api` 로 릴리스 원문을 다시 확인했고, 다른 도구는 조사 에이전트가 한 번 읽은 것이다.

## 먼저 — 다섯 가지 밖의 위험
- 이 Mac 에 설치된 0.2.0 은 설치(11-18) 뒤 열린 흔적이 없다. 실제 데이터 폴더의 파일이 설치 뒤 하나도 바뀌지 않았고, 설치본이 새로 띄운 셸 지킴이도 없다(두 방법으로 봤지만 단정은 아님). 사용자는 여전히 다른 도구에서 매일 일한다.
- 61~66 은 공개 판에 없고, 58 · 59 · 61~66 의 e2e 는 한 번도 돌지 않았다(돌려야 할 목록이 단계 문서마다 쌓여 있다). '매일 쓰기' 에는 새 기능보다 **e2e 한 번 → 0.3.0** 이 먼저다. 아이디어가 아니라서 다섯에 넣지 않았다.
- 개발 · 시험 실행이 남긴 셸 지킴이가 여전히 열 개 넘게 떠 있다(가장 오래된 것은 8일). 61 의 정리 화면은 공개 판에 없고, 남기는 원인은 아직 조사하지 않았다.

## 문제와 근거

대상은 이 Mac 의 사용자 본인이다. Claude · Codex 를 여러 저장소의 worktree 에서 돌리는 1인 개발자다.
문제: Taskminal 로 넘어오면 지금 매일 하는 일 중 무엇이 끊기거나 불편해지나. 범위는 사용자가 지금 쓰는 도구의 CLI 와 데이터 폴더(개수 · 시각만), Claude · Codex 세션 파일의 개수, Taskminal 코드, 바깥 릴리스 노트다. 다른 도구의 화면을 조작하지 않았고 사용자에게 묻지 않았다.

## 다음 검증 (e2e 없이)

**가장 위험한 가정(1번)**: 사용자가 휴대폰 알림에서 하는 일이 '보기' 로 충분하고, 가린 제목을 ntfy · 메신저 같은 바깥 통로로 받는 것을 받아들인다. 틀리면 1 은 같은 망 페이지 · 답하기(큰 비용)부터 해야 하거나 보류된다.
- 방법: 사용자에게 두 가지를 묻는다(가장 싼 확인). ① 지금 휴대폰 알림을 받고 하는 일 — 보기만 · 허락 · 질문에 답하기 · 새로 시키기 중 무엇이 잦은가. ② 알림을 받을 통로 — ntfy(앱 하나 · 주소 하나 · 계정 없음, 추천) · 이미 쓰는 메신저 웹훅 · 바깥 통로는 싫음.
