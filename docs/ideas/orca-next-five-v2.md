## 단계 → verify

1. 44 내장 편집·리뷰: 기존 파일 탐색의 텍스트에서 편집 모드, 저장/되돌리기, 바뀐 디스크 충돌에서 초안 보존·다시 읽기·명시적 재확인. 미리보기의 비밀값 가림 결과를 원문으로 덮어쓰지 않도록 별도 편집 읽기 계약을 사용하고 민감 파일은 기존 차단을 유지한다. 최대2MB·UTF8·일감 루트/심볼릭 링크 경계·동시 저장 잠금을 main에서 검증한다. diff 줄별 코멘트 초안을 정확한 파일/변경 서명에 묶어 일괄 대화 첨부·resolve, 변경 후 낡은 코멘트를 조용히 재사용하지 않는다. verify: 실제 임시 파일 수정·경로 탈출/심볼릭 링크·저장 전 외부 변경·취소 보존·코멘트 전송 e2e 및 단위/정확한 변이.
2. 45 병렬 에이전트: 기존 workflow 순차 실행은 기본 유지, 명시한 동시 실행 한도와 단계 의존성으로 독립 단계를 동시에 실행하고 의존 단계는 선행 완료 뒤 시작한다. 단계별 상태·실패·질문·재시도와 결과 묶음을 유지한다. worker별 별도 worktree 옵션은 실제 git checkout을 만들고 실행 pane의 cwd를 고정하며 기존 일감 폴더를 바꾸지 않는다. 실패/중단은 해당 run의 프로세스만 종료하고 checkout은 자동 삭제하지 않는다. verify: 가짜 공급자와 임시 Git에서 실제 독립 경로·동시 진행·fan-in·실패/중단/재시작·중복 방지. 실계정 메시지 전송은 하지 않는다.
3. 46 브라우저 자동화: 명시한 일감/탭을 대상으로 CLI snapshot·click·fill·screenshot·navigate 지원. snapshot 참조는 탭/페이지 탐색 세대에 묶고 페이지가 바뀌면 오래된 참조를 거절한다. 비밀번호/입력값·비밀값 가림, 앱 API/파일/내부URL 차단 및 기존 웹 격리를 유지한다. verify: 실제 로컬 사이트에서 snapshot→fill→click→변경 결과·탐색 후 옛 ref 거절·다른 탭/닫힌 탭 거절·캡처를 CLI 통합 e2e.

## 실패·재시도·취소 계약

- 결과를 모를 때: 저장/작업 생성/원격 전송에 request ID와 결과 상태를 표시한다. 성공을 추정하거나 자동 재전송하지 않는다. 읽기로 현재 파일 서명·이미 생성된 checkout/일감·원격 session ID부터 확인한다.
- 다시 시도: 같은 생성 request ID는 같은 결과로 이어가고 완료 자원을 다시 만들지 않는다. 파일 충돌은 디스크 최신 내용을 읽고 사용자 편집을 보존해 비교한 뒤 새 서명으로 저장한다. 네트워크 끊김의 읽기만 재시도하고 쓰기는 멱등 ID로 결과 조회한다.
- 이중 입력: 파일/루트·workflow run·issue create·remote request 단위 잠금과 main 검증. UI busy만으로 중복을 막지 않는다. 빠른 두 IPC의 실제 시험을 둔다.
- 취소·뒤로: 미전송 편집/코멘트 초안은 보존하며 명시적 버리기로만 지운다. 패널 닫기는 이미 시작한 run·서버 session·git worktree를 취소/삭제하지 않는다. 별도 중단은 소유한 프로세스만 종료한다. 만든 checkout과 이슈 연결은 실패했다고 숨기지 않는다.
- 대상 소멸: 열린 확인창 이후 일감/파일/탭/worker가 사라지면 ID로 재탐색하고 실행을 거절한다. 저장 내용은 클릭 당시 snapshot, 조회의 늦은 응답은 세대로 버린다.
- 중간 단계 실패: checkout 생성→pane 준비→agent 전송 중 뒤 단계가 실패하면 생성된 checkout/session ID를 보존해 결과에 표시하고, 준비 중인 소유 프로세스·구독만 정리한다. 다시 시도는 이미 만든 checkout을 확인한 뒤 실패한 준비/전송 단계부터 시작한다. 시험: checkout 성공 뒤 pane 준비 실패를 주입하고 재시도에서 checkout 생성 횟수1·정확한 cwd·유실 없는 오류를 확인한다.
- 붙는 중: 원격 연결·프로세스 준비·브라우저 명령은 시간 제한과 오류/재시도 글자를 제공한다. pending을 무한 로딩으로 남기지 않는다.
- 부수 요청: 알림·복귀·주기 폴링은 한 번에 하나만 수행하고 앞 요청이 끝나기 전에는 추가 요청을 쌓지 않는다. 패널이 안 보일 때 폴링을 중단한다. 시험: 느린 조회 중 알림3회와 패널 닫기를 주입해 동시 요청1·닫힌 뒤 새 요청0을 확인한다.
- 읽기와 쓰기가 겹칠 때: 쓰기 시작/완료와 이동 때 읽기 번호를 갱신하여 옛 응답을 무효화한다. 건너뛴 요청은 앞 요청이 끝난 뒤 다시 한 번 읽는다. 값을 비우고 다시 받는 중에는 오류 대신 받는 중으로 표시한다. 설정/계정/cwd는 실행 직전 현재 값으로 검증한다.
- 종료4경로: 앱 종료·창 닫기·renderer reload·충돌에서 편집 초안/코멘트와 원격 session 수명을 구분한다. 로컬 열린 run은 기존 interrupted/unknown 정책을 유지하고 원격 server가 소유한 셸은 클라이언트 종료만으로 죽이지 않는다. 서버 종료는 명시적 stop일 때 소유 세션만 정리한다.
- 저장 충돌/거절(412): 디스크 또는 서버 최신 서명을 표시하고 초안을 유지한다. 확인 없이 강제 덮어쓰기하지 않는다. 실패한 요청 재전송 시 완료된 저장을 중복 적용하지 않는 시험을 둔다.
