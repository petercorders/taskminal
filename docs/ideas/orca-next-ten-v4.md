# Orca 비교 네 번째 — 57단계 뒤에도 남은 꼭 필요한 열 가지

일자: 2026-11-17. 상태: **조사 · 결정 기록, 구현 승인 아님**(`/harness-run idea Orca랑 비교 했을 때 꼭 개발 필요한 10가지 e2e 테스트는 하지마`).
기준: Taskminal `origin/main` 20947de(57단계 · PR #9 까지) · Orca 설치본 1.4.257 CLI · Orca 공식 문서 a9a0e8cd(2026-11-11 소스 사본, 59쪽).
앞선 세 번(v1 → 36~40, v2 → 44~48, v3 → 51~55)과 31~35 · 50 · 56 · 57단계에서 만든 것은 다시 고르지 않는다.
공개 저장소라 사용자 환경의 관찰값(개수 · 다른 도구 이름)은 일반화해 적는다. 공개 릴리스는 계속 보류 중이다.

**사용자 지시: e2e 시험은 하지 않는다.** 이 기록을 쓰는 동안 e2e 를 돌리지 않았고(아래 1번의 측정값은 지시 전에 잰 것), 이어질 구현도 단위 시험 · 타입 · 경계 검사까지만 하고 e2e 로만 볼 수 있는 것은 '돌려야 할 목록' 으로 남기는 것으로 읽었다(13~15단계 선례). 구현에서 e2e 를 쓰기만 하고 안 돌리는 것까지 막는 뜻인지는 묻지 않았다 — 쓰지도 않는 쪽으로 계획한다.

## 문제와 근거

대상은 이 Mac 의 사용자 본인이다. Claude · Codex 를 여러 저장소의 worktree 에서 돌리는 1인 개발자이고, Orca 를 매일 쓰면서 Taskminal 을 그 안에서 개발한다.
문제: Taskminal 로 옮겨 오면 Orca 에서 당연하던 것 중 무엇이 아직 없거나 깨지나. 비교 범위는 Orca 문서 59쪽의 기능 · CLI 도움말 · 사용자의 Orca 사용 흔적과 Taskminal 코드다. Orca 의 모든 버전 · 기능을 감사한 것은 아니고, Orca 앱 화면을 직접 조작해 보지는 않았다.

## 대안과 선택

근거의 세기로 두 묶음으로 나눈다. **가**는 재거나 코드로 확인한 결함 · 빈자리이고, **나**는 사용자 요청이나 사용 흔적은 있으나 얼마나 쓸지는 모르는 것이다. 점수는 매기지 않는다.
