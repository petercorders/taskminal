# Orca 비교 다섯 번째 — 0.2.0 뒤에 꼭 필요한 다섯

일자: 2026-11-18. 상태: **조사 · 결정 기록, 구현 승인 아님**(`/harness-run idea Orca랑 비교 했을 때 꼭 개발 필요한 5가지 또 진행해줘`).
기준: Taskminal `origin/main` d957dce(59단계 · 0.2.0 공개까지) · Orca 설치본 1.4.257 CLI · Orca 공식 문서 a9a0e8cd(2026-11-11 소스 사본, 59쪽).
앞선 네 번(v1 → 36~40, v2 → 44~48, v3 → 51~55, v4 의 1~5 → 58)과 56 · 57 · 59단계에서 만든 것은 다시 고르지 않는다. v4 에서 남긴 6~10 은 그대로 옮기지 않고, 그 뒤에 새로 본 것과 함께 다시 따졌다.
공개 저장소라 사용자 환경의 관찰값(개수 · 다른 도구 이름)은 일반화해 적는다. **e2e 는 돌리지 않았다**(사용자 지시가 이어진다) — 조사는 코드 읽기와 읽기 전용 명령뿐이다.

## 먼저 — 다섯 가지 밖의 위험
58 · 59단계는 e2e 없이 0.2.0 으로 공개됐다. 돌려야 할 목록이 두 단계 문서에 쌓여 있다(`docs/stages/58-…` · `59-…`). 새 기능을 더 얹기 전에 한 번 돌리는 것을 권한다 — 'Orca 비교' 항목이 아니라 아래 다섯에 넣지 않았다.

## 문제와 근거

대상은 이 Mac 의 사용자 본인이다. Claude · Codex 를 여러 저장소의 worktree 에서 돌리는 1인 개발자이고, 지금은 Orca 를 매일 쓰며 Taskminal 0.2.0 을 막 설치했다.
문제: 이제 Taskminal 을 매일 쓰기 시작하면 Orca 에서 당연하던 것 중 무엇이 먼저 걸리나. 비교 범위는 Orca 문서 · CLI, 사용자의 Orca 사용 흔적, Taskminal 코드, 그리고 58 · 59단계와 0.2.0 출시 중에 이 Mac 에서 본 것이다. Orca 앱 화면을 직접 조작해 보지는 않았다.

## 다음 검증 (e2e 없이)

**가장 위험한 가정(1번)**: 남의 지킴이(다른 데이터 폴더 · 옛 판)에 붙어 목록을 물어도 그 지킴이의 셸과 붙어 있는 앱에 영향이 없고, 어느 지킴이가 '쓰는 중' 인지 틀리지 않게 가릴 수 있다. 틀리면 사용자의 살아 있는 셸을 끝낸다 — 되돌릴 수 없다.
- 방법: 읽기 전용 기술 스파이크. 임시 데이터 폴더로 지킴이 하나를 띄워(가짜 셸) ① 프로세스 목록에서 소켓 · 데이터 폴더를 읽어 내는지 ② 두 번째 연결이 `hello` → `list` 만 하고 끊었을 때 첫 연결의 출력 · 세션이 그대로인지 ③ 판(프로토콜 번호)이 다른 연결에 지킴이가 어떻게 답하는지를 단위 시험으로 본다. 이 Mac 에 떠 있는 실제 지킴이에는 붙지 않는다.
- 성공: 세 가지 모두 영향 없이 읽힘. 중단: 두 번째 연결이 첫 연결을 떼어 낸다 → 목록은 프로세스 정보(시작 시각 · 자식 수 · 데이터 폴더)만으로 보이고 셸 내용은 묻지 않는다. 판정 보류: 판이 다른 지킴이가 답하지 않는다 → '판이 달라 내용을 볼 수 없음' 으로만 표시.
- 실행 상태: **설계만, 실행하지 않음.**

- 3: 먼저 58b — 사용자가 0.2.0 의 대화 pane 에서 Claude 에게 `taskminal` 명령을 아는지 한 번 물어본다(실제 계정 1회, 사용자 손으로). codex 는 `codex --help` · 설정 문서에서 지침 키를 찾는다.
