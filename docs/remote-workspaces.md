# 원격 작업 공간

기능 브랜치 48단계의 원격 작업 공간은 서버가 파일·Git 저장소·셸·Claude/Codex 프로세스를 소유한다. 데스크톱의 **원격 작업 공간** 도구에서 접속하며 앱 종료·연결 해제로 서버 작업을 종료하지 않는다. 공개 0.1.2에는 아직 포함되지 않았다.

## 서버 실행

서버 컴퓨터에 같은 버전의 Taskminal 및 사용할 에이전트 CLI를 설치한다. 개발 체크아웃은 의존성 설치와 `npm run build` 후 다음처럼 실행한다. node-pty ABI를 맞추기 위해 포함된 Electron을 Node 모드로 실행하는 launcher를 사용한다.

```sh
resources/bin/taskminal-server --root /srv/projects --data /srv/taskminal-state --port 4788
```

Windows 개발 체크아웃은 `resources\bin\taskminal-server.cmd --root C:\projects --data C:\taskminal-state --port 4788`을 사용한다. 배포 폴더의 resources/bin에도 launcher가 포함된다. 서버 OS·CPU와 맞는 배포본이 필요하다. Windows/Linux 실기기 서버 검증은 별도다.

`--root`는 작업 공간을 열 수 있는 허용 폴더, `--data`는 그 밖에 둔 서버 기록 폴더다. 서버는 **127.0.0.1에만** 바인딩한다. 시작 출력에는 서버 주소와 토큰 파일 경로만 표시한다. 자동 생성 토큰은 `<data>/token`에 0600으로 보관되며 서버 기록 폴더는 0700이다. 토큰을 데스크톱 접속 칸에 입력한다. 클라이언트는 이를 main 프로세스 메모리에만 보관하고 앱 상태·localStorage에 저장하지 않는다.

다른 컴퓨터에서는 SSH 터널을 연다.

```sh
ssh -N -L 4788:127.0.0.1:4788 user@server
```

데스크톱에서 `http://127.0.0.1:4788`과 서버 토큰을 입력한다. HTTPS 게이트웨이를 별도로 구성했다면 기본 HTTPS 주소도 연결할 수 있다. 클라이언트는 TLS 인증서 검증을 유지하고 redirect를 따라 토큰을 전달하지 않는다. 이 작업에서 실제 호스트·게이트웨이는 설치하지 않았다.

## 사용·재접속

허용 루트 안의 상대 폴더를 열거나 기존 서버 작업 공간을 고른다. 파일 편집은 2MB 이하 UTF-8 원문이며 외부 변경 시 초안을 보존하고 최신 내용과 비교한다. `.env`, 인증 키, `.git` 등은 기존 파일 규칙으로 차단한다. Git 탭은 상태·diff를 읽으며 자동 commit/push를 하지 않는다.

터미널은 서버의 실제 PTY를 사용하는 **출력·줄 입력 콘솔**이다. Ctrl+C와 명시적인 셸 종료를 지원한다. xterm 전체 TUI·ANSI 표시·화면 크기 동기화는 후속 범위다. Claude/Codex는 서버에 설치·인증된 CLI를 사용하며 구조화된 기록·도구 허락·질문·턴 중단을 제공한다. 실제 계정 인증은 사용자가 서버에서 한다.

연결을 끊거나 앱을 종료한 뒤 다시 연결하여 같은 작업 공간·세션 ID를 선택한다. 서버가 살아 있는 동안 터미널 뒤쪽 1백만 글자와 실행 중인 에이전트를 이어 본다. 터미널 출력은 서버 메모리에만, 가린 대화 기록·메타데이터는 서버 기록 폴더에 보관한다. 서버 자체 재시작은 실행 중 프로세스 생존을 보장하지 않는다. 이전 터미널은 종료 상태로 표시하고 대화는 보관된 세션 ID/기록에서 다음 메시지로 이어 간다.

## 응답 유실·잠금

생성·저장·셸 입력·대화 전송에는 요청 ID와 fingerprint를 사용한다. 같은 요청 ID를 재전송하면 완료 결과를 재사용하며 내용을 바꿔 재사용하면 거절한다. 실행 전 pending fence를 디스크에 기록한다. 서버가 실행 도중 중단되어 완료 여부를 알 수 없는 요청은 자동으로 다시 실행하지 않는다. 출력·파일·기록을 확인한 뒤 **결과 확인 후 새 요청 번호로 준비…**를 사용하여 명시적으로 새 요청을 준비한다. 버튼 자체가 명령을 보내지는 않는다.

같은 서버 기록 폴더는 한 프로세스만 열 수 있다. 비정상 종료 후 `server.lock`이 남으면 파일에 적힌 PID가 더 이상 실행되지 않는지 운영자가 확인한 뒤 잠금을 정리한다. 실행 중인 서버의 잠금을 지우지 않는다. 토큰 교체는 서버를 중지한 뒤 토큰 파일을 재발급하고 클라이언트에 다시 입력하는 별도 운영 작업이다.

토큰은 해당 서버 사용자 권한의 셸·에이전트 실행 권한이다. 허용 루트는 파일 API와 시작 cwd의 범위이며 명령 실행을 OS 수준에서 sandbox하는 기능이 아니다. 별도의 전용 OS 계정·SSH 접근 제어가 필요한 환경에서는 서버 운영자가 구성한다. 네이티브 모바일 앱은 이 단계에 포함되지 않는다.
