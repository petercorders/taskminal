# 0.2.0 출시 — 결과와 준비 기록

## 결과 (2026-11-18 게시 완료)
사용자 "게시 진행하고 자동업데이트 한번 해봐봐" · "알아서 해줘" 에 따라 게시했다. e2e 는 돌리지 않았다(사용자 지시가 이어짐 — 58 · 59단계의 화면 동작은 미확인인 채로 나갔다).
- **릴리스**: [v0.2.0](https://github.com/petercorders/taskminal/releases/tag/v0.2.0) — latest, id `449378765`. 태그와 앱 산출물 소스는 `057a73609af54df3d4d9450ff2ae4476363421f0`(준비 PR #14 의 머리, main 0a830b5 에 포함).
- **네 OS CI**: [`44199629993`](https://github.com/petercorders/taskminal/actions/runs/44199629993) 그 커밋에서 darwin-arm64 · darwin-x64 · win32-x64 · linux-x64 성공. Windows · Linux 설치 파일은 이 실행의 산출물이다.
- **Mac**: 이 Mac 에서 `npm run release` 종료 0 — 두 칩 Developer ID 서명 · Apple 공증 성공 2건 · `check-package --release` 통과. 따로 확인: `codesign --verify --deep --strict` · `spctl` = accepted / Notarized Developer ID · `stapler validate` 통과(두 칩). CI 의 ad-hoc Mac 산출물은 올리지 않았다.
- **파일 22개**: OS별 manifest(소스 · 버전 · 크기 · SHA-256) · `latest*.yml`(SHA-512 · 크기, Mac 은 두 zip 포함) 대조 뒤 초안 릴리스에 올리고, 원격 22개의 이름 · 크기 · SHA-256 이 로컬과 같은 것을 본 다음 공개했다. `builder-debug.yml` 은 뺐다.
- **공개 내려받기**: 인증 없이 설치 파일 5종 + Mac zip 2개를 받아 SHA-256 일치, `latest*.yml` · `SHA256SUMS` 는 올린 것과 같다.
- **홈페이지**: 다운로드는 `releases/latest` API 에서 읽으므로 다시 배포하지 않았다 — API 가 `v0.2.0` · 자산 22개를 돌려준다. README 의 태그 예시만 바꿨다.
- **자동 업데이트 0.1.2 → 0.2.0**: 공개된 0.1.2(Apple Silicon zip, 해시 · 공증 확인)를 임시 폴더 · 임시 데이터로 띄워 확인했다. 스스로 0.2.0 을 찾아 받았고(`downloaded`), 설치를 요청하자 2초 뒤 종료 → 묶음이 0.2.0 으로 바뀜 → 다시 뜸(4초). 바뀐 묶음은 Notarized Developer ID 로 받아들여지고, 업데이트 전부터 돌던 셸 지킴이가 그대로 살아 있었다. 다시 뜨는 앱이 실제 데이터를 열지 않게 그동안만 `launchctl setenv` 로 임시 데이터 폴더를 지정했고(빈 시험용 앱으로 전달되는 것을 먼저 확인) 끝난 뒤 풀었다 — 실제 데이터 폴더는 바뀐 파일이 없다. 설치 단추를 사람이 누르는 대신 디버깅 포트로 앱의 업데이트 API 를 불렀다.
- 미확인: Intel Mac · Windows · Linux 에서의 자동 업데이트, 0.1.2 를 실제로 쓰던 데이터(일감 · 셸)가 있는 상태에서의 업데이트, 58 · 59단계의 화면 동작.

# 준비 기록 — 상태와 남은 승인 (게시 전)

2026-11-18 사용자 "이거 끝나면 업데이트 한번하게 준비해줘". **준비까지만 했다 — 태그 · GitHub 릴리스 게시 · 공증 제출 · 사이트 배포 · `/Applications` 설치는 하지 않았다**(`docs/development.md` 의 승인 규칙: 공개 릴리스는 별도 명시적 요청).
브랜치 `release/0.2.0-prep`(base `origin/main` 2d6f4fc = 59단계까지). 지금 공개 버전은 0.1.2(태그 `v0.1.2`, 43단계)이고 그 뒤 44~59단계가 출시되지 않은 채 main 에 있다.

## 게시 전에 정할 것 (사용자 승인)
1. **e2e 를 한 번 돌릴지 — 추천: 돌린다.** 58 · 59단계는 지시대로 e2e 없이 병합했다. 공개본에 들어가므로 게시 전 전체 e2e 1회(약 10분, 이 Mac 에 앱 창이 뜬다)를 권한다. 먼저 볼 목록: `docs/stages/58-remote-input-guide-gestures.md` · `docs/stages/59-agent-icons.md` 의 '돌려야 할 e2e'. 실패가 나오면 고친 뒤 다시 준비한다.
2. **네 OS CI** — `.github/workflows/multi-platform.yml` 은 main push 로는 돌지 않는다(옛 브랜치 push · 수동 실행만). 마지막 실행은 0.1.2 때(2026-11-13)라 44~59단계는 Windows · Linux 에서 한 번도 빌드 · 실행되지 않았다. 준비 PR 을 연 뒤 이 브랜치로 수동 실행을 걸어 둔다 — 실행 주소와 결과는 준비 PR 본문에 적는다(이 문서를 쓸 때는 결과가 없다). 게시하지 않는 워크플로다.
3. **Mac 서명 · 공증** — `npm run release`(두 칩, dmg + zip + `latest-mac.yml`, Apple 에 공증 제출). 게시는 하지 않는 명령이지만 Apple 에 제출이 나간다.
4. **게시** — 태그 `v0.2.0` · GitHub 릴리스(설치 파일 · blockmap · `latest*.yml` · manifest · `SHA256SUMS` — 0.1.2 는 22개). 게시하는 순간 0.1.2 사용자의 자동 업데이트가 이 버전을 받는다.
5. **사이트 · README** — 다운로드 주소가 0.1.2 를 가리킨다(`site/index.html` · `site/en/index.html` · `site/docs/` · `README.md`). `site/` 를 main 에 push 하면 Pages 가 배포된다 — 게시와 같은 때에.
6. **이 Mac 의 설치본** — `/Applications` 의 Taskminal 을 0.2.0 으로 바꿀지(자동 업데이트로 받을지 · 직접 설치할지).

## 미검증 · 위험
- 58 · 59단계의 실제 화면 동작(끌어 놓기 · OSC 52 · 탭 끌기 · 로고 모양 · 새 설정 행) — e2e · 화면 리뷰 없음. 사용자가 임시 데이터로 띄운 빌드에서 직접 보는 중.
- 대화 claude 에 붙이는 안내 인자(`--append-system-prompt`)가 실제 claude 에서 문제없이 도는지.
- 0.1.2 → 0.2.0 자동 업데이트 경로는 게시해야만 확인된다. 받은 사용자는 되돌릴 수 없으니 게시 직후 한 대에서 먼저 확인한다.
- Windows · Linux 는 44단계 뒤로 실제 환경 확인이 없다.
