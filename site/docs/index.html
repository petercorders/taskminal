처음 3분

  1. 프로젝트 폴더로 일감을 만드세요.

    앱의 ‘새 일감’을 누르고 폴더를 고릅니다. 일감은 폴더·탭·대화·셸을 함께 묶는 단위예요.

  2. 대화 또는 터미널로 시작하세요.

    Claude·Codex 대화를 고르거나 터미널을 엽니다. AI CLI가 아직 없다면 터미널부터 사용할 수 있어요.

  3. 셸을 꺼내고, 다른 일감으로 옮겨 보세요.

    Mac은 ⌘J, Windows·Linux는 Ctrl+J로 셸을 꺼냅니다. 다른 일감으로 이동했다 돌아와도 하던 화면과 세션을 이어 갑니다.

필요한 명령을 모르겠다면 ⌘P / Ctrl+P로 명령 팔레트를 열고 이름으로 찾으세요. ‘파일 탐색’, ‘대화 기록 찾기’, ‘설정’처럼 입력하면 됩니다.

설치와 OS 선택

홈페이지 다운로드 목록에서 사용할 컴퓨터의 OS와 칩을 고르세요. 검증을 거쳐 공개된 파일만 연결하며, 없는 파일은 ‘출시 준비 중’으로 표시합니다.

Linux · x64.AppImage / .debAppImage는 실행 권한을 준 뒤 열고, Debian·Ubuntu 계열은 deb 설치 프로그램을 사용할 수 있어요. 배포판별 시스템 의존성이 필요할 수 있습니다.

공개 Mac 빌드는 Developer ID 서명과 Apple 공증을 거쳐 제공합니다. OS와 칩이 다른 파일은 실행되지 않을 수 있으니, 자동 추천이 없으면 직접 선택하세요.

Windows·Linux는 초기 지원인 베타입니다. 공개 여부와 해당 버전의 검증 범위는 릴리스 노트에서 함께 확인하세요.

Linux에서 한글이 네모로 보인다면

최소 설치 환경에는 한글을 그릴 CJK 시스템 폰트가 없을 수 있습니다. Debian·Ubuntu에서는 다음 명령으로 폰트를 설치한 뒤 Taskminal을 다시 여세요. 다른 배포판은 동등한 CJK 폰트 패키지를 설치합니다.

sudo apt update
sudo apt install fonts-noto-cjk fontconfig
fc-cache -f

첫 Windows 버전에서 다른 점

터미널은 기본적으로 PowerShell을 사용합니다. 포트 자동 감지, 엄격한 실행 폴더 확인이 필요한 worktree 정리, 추가 계정의 TUI 전환은 아직 지원하지 않습니다. 확인할 수 없는 worktree는 안전을 위해 삭제하지 않아요.

새 버전은 앱 메뉴의 ‘업데이트 확인’ 또는 설정 → 정보에서 확인합니다. 앱에서 업데이트를 받을 수 없는 설치 형태는 홈페이지의 새 설치 파일을 사용하세요.

Claude · Codex 연결

Taskminal은 사용자의 컴퓨터에 설치된 Claude Code·Codex CLI를 실행합니다. 각 서비스의 계정·로그인이 필요하며 이용 요금과 접근 권한도 그 계정에 따릅니다.

  1. 사용할 에이전트의 CLI를 설치하고, 일반 터미널에서 해당 CLI 안내에 따라 로그인합니다.
  2. 프로젝트 폴더의 터미널에서 claude 또는 codex가 실행되는지 확인합니다.
  3. Taskminal에서 새 일감의 시작 화면으로 해당 에이전트를 고르거나, 명령 팔레트에서 ‘새 대화 (Claude)’ 또는 ‘새 대화 (Codex)’를 선택합니다.
  4. 작업을 요청하고, 승인·질문 카드가 나타나면 내용을 확인한 뒤 답합니다.

‘CLI 없음’ 또는 ‘로그인 필요’가 보이면 앱을 다시 설치하기 전에 CLI 실행과 로그인을 먼저 확인하세요. 설치 후에는 대화 화면의 다시 찾기·재시도를 사용합니다. 계정별 상태는 ‘사용량·계정’에서 볼 수 있어요.

추가 계정은 ‘사용량·계정’에서 관리할 수 있습니다. 기본 계정 로그인은 기존 CLI에서 진행하고, 추가 계정은 앱 전용 폴더를 사용합니다. 대화 기록의 저장본은 비밀값 패턴을 가리지만, 에이전트에 보낸 원문은 해당 서비스가 처리합니다.

일감과 작업 도구

폴더별 일감을 만들고 상태·메모로 정리하세요. 탭은 작업 화면을 나누고, 분할은 같은 일감의 대화와 셸을 나란히 보여 줍니다.

맥락 확인하기

파일 탐색에서 텍스트·Markdown·그림·PDF를 미리 보고, 확인한 파일이나 범위를 대화에 첨부합니다. 대화 기록 검색으로 앞서 결정한 내용을 찾으세요.

변경 검토하기

변경 보기에서 diff를 읽고 선택한 변경을 커밋합니다. GitHub PR·push와 worktree 관리는 필요한 외부 도구와 권한이 갖춰진 저장소에서 사용합니다.

화면 함께 보기

내장 브라우저에서 개발 중인 페이지를 확인합니다. 여러 브라우저 탭을 일감에 묶어 두고 필요한 화면으로 돌아올 수 있어요.

반복 작업 정리하기

빠른 명령은 자주 실행하는 셸 명령을 모읍니다. 에이전트 작업 흐름과 예약·결과함으로 반복 요청과 결과를 관리합니다.

작업 도구 단추가 보이지 않는 작은 창에서는 ‘작업 도구 선택’ 메뉴나 명령 팔레트를 사용하세요.

먼저 익힐 단축키

주요 앱 명령은 Mac에서 Command, Windows·Linux에서 Control을 사용합니다. 설정에서 키를 바꿀 수 있고, 나머지 명령은 팔레트에서 찾을 수 있어요.

저장 · 백업 · 종료

앱을 닫아도 셸은 계속 돌아갈 수 있어요

셸은 앱 밖의 지킴이가 유지합니다. 앱을 다시 열면 같은 셸에 연결하고 출력을 복원해요. 모든 셸을 멈추려면 앱 메뉴의 ‘셸까지 모두 끝내기’를 사용하세요. 실행 중인 작업을 확인한 뒤 종료합니다.

백업은 작업 공간 상태를 위한 기능이에요

설정 → 백업 · 되돌리기에서 백업을 확인하거나 일감·설정을 내보내고 가져올 수 있습니다. 프로젝트 소스 파일과 외부 서비스의 데이터까지 백업하는 기능은 아니므로 Git 등으로 별도 관리하세요.

로컬 저장과 외부 연결

Taskminal의 일감·설정·기록은 로컬에 저장됩니다. Claude Code·Codex는 각자의 서버에 연결하고, 내장 브라우저·GitHub 도구·업데이트 확인은 사용 중인 서비스에 연결합니다. 비밀값 패턴 가리기는 완전한 비밀 탐지가 아니므로, 기록이나 화면을 공유하기 전에는 내용을 확인하세요.

문제 해결

셸이 연결되지 않거나 이전 작업이 보이지 않아요.

명령 팔레트에서 ‘셸 지킴이 보기’를 열고 연결 상태와 셸 목록을 확인하세요. 다시 연결을 먼저 시도하고, 지킴이를 다시 시작하면 기존 셸이 끝날 수 있다는 안내를 확인하세요. 사용자 데이터 폴더를 지우는 방식으로 복구하지 마세요.

에이전트는 터미널에서 되는데 대화 칸에서는 안 돼요.

CLI 설치 경로와 로그인을 확인한 뒤 대화 화면에서 다시 찾기·재시도를 사용하세요. 설치한 셸과 앱이 사용하는 환경이 다를 수 있습니다. ‘사용량·계정’의 상태와 오류 메시지도 함께 확인하세요.

업데이트를 받지 못했어요.

설정의 ‘정보’에서 현재 상태를 확인하고 다시 시도하세요. 건너뛴 버전은 ‘다시 알리기’로 되돌릴 수 있습니다. 계속 실패하면 홈페이지에서 OS·칩에 맞는 최신 설치 파일을 내려받으세요.

문제를 제보할 때 무엇을 보내면 되나요?

앱 버전, OS·칩, 재현 순서와 실제 결과를 GitHub 이슈에 남겨 주세요. 명령 팔레트의 ‘오류 기록 열기’로 로그를 볼 수 있습니다. 공유 전 비밀값·계정 정보·개인 경로를 확인하세요.
